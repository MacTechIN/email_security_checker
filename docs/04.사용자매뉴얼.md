# MailShield 사용자 매뉴얼

## 1. 서비스 소개

MailShield Agent는 Windows에서 백그라운드로 실행되며 이메일의 개인정보 유출, 위험 첨부파일, 스팸·피싱 의심 메일과 등록된 보호 확장자 파일의 전송을 감시합니다.

## 2. 설치 순서

관리자 권한 PowerShell에서 반드시 저장소 루트로 이동한 뒤 다음 순서로 실행합니다. 오류 화면의 `PS C:\WINDOWS\system32>`는 저장소가 아닌 Windows 시스템 폴더이므로 `./installer`를 찾을 수 없습니다.

```powershell
Set-Location "C:\Users\이상진\Documents\email_checker"
Set-ExecutionPolicy -Scope Process Bypass -Force
.\installer\Publish-MailShieldAgent.ps1
.\installer\Verify-MailShieldPackage.ps1
.\installer\Install-MailShieldAgent.ps1
.\installer\Verify-MailShieldService.ps1
```

설치 후 서비스 이름은 `MailShieldAgent`입니다.

## 3. 기본 설정

설정 파일:

```text
agent\MailShield.Agent\appsettings.json
```

주요 항목:

```json
{
  "MailShield": {
    "ControlPlaneUrl": "https://your-control-plane.example",
    "ControlPlaneApiKey": "운영용-에이전트-키",
    "TenantId": "조직-GUID",
    "DeviceId": "장치-ID",
    "HeartbeatSeconds": 30,
    "PolicyRefreshSeconds": 300,
    "ImapHost": "imap.example.com",
    "ImapPort": 993,
    "MailAddress": "user@example.com",
    "ImapFolders": "INBOX,Sent"
  }
}
```

`ControlPlaneApiKey`와 IMAP 앱 비밀번호는 일반 사용자에게 노출되는 파일에 저장하지 마십시오. IMAP 앱 비밀번호는 현재 다음 환경변수로 임시 설정할 수 있습니다.

```powershell
$env:MAILSHIELD_IMAP_APP_PASSWORD = "앱-비밀번호"
```

운영 환경에서는 Windows Credential Manager 또는 DPAPI 기반 보안 저장소를 사용해야 합니다.

## 4. 서비스 사용 명령

```powershell
Get-Service MailShieldAgent
Start-Service MailShieldAgent
Stop-Service MailShieldAgent
Restart-Service MailShieldAgent
```

서비스가 정상이라면 `Status`가 `Running`, 시작 유형이 `Automatic`이어야 합니다.

## 5. 감시 동작

설정이 모두 있으면 Agent는 다음 순서로 동작합니다.

1. 중앙 서버에 heartbeat를 전송합니다.
2. 최신 정책을 받아 DPAPI로 암호화해 로컬에 저장합니다.
3. `INBOX`와 `Sent`에 각각 IMAP IDLE 연결을 시작합니다.
4. 새 메일이 도착하면 UID 기준으로 메일을 가져옵니다.
5. 본문, 제목, 첨부파일 메타데이터를 DLP 정책으로 검사합니다.
6. 위험 발견 시 사건 로그를 남기고 이후 관리자 알림 연결 지점으로 전달합니다.

IMAP 설정이 없으면 Agent는 heartbeat 전용 모드로 실행합니다.

## 6. 로그 확인

Windows Service 로그는 기본적으로 .NET 호스트 로그와 Windows 이벤트 로그를 사용합니다. 개발 단계에서는 다음 위치의 정책 캐시를 확인할 수 있습니다.

```text
%LOCALAPPDATA%\MailShield\policy.bin
```

정책 캐시는 Windows DPAPI로 암호화됩니다. 파일을 직접 열거나 복사해 내용을 확인하지 마십시오.

## 7. 문제 해결

### 서비스가 시작되지 않는 경우

- 관리자 권한으로 실행했는지 확인합니다.
- `Get-Service MailShieldAgent`로 서비스 존재 여부를 확인합니다.
- `Verify-MailShieldService.ps1`를 실행합니다.
- Windows 이벤트 뷰어의 `Windows 로그 → 시스템`을 확인합니다.

### IMAP 연결이 실패하는 경우

- IMAP 호스트와 포트가 올바른지 확인합니다.
- 포트 993과 TLS 연결을 지원하는지 확인합니다.
- 일반 비밀번호가 아닌 공급자에서 발급한 앱 비밀번호를 사용합니다.
- 공급자의 동시 연결 제한과 IDLE 지원 여부를 확인합니다.
- `MAILSHIELD_IMAP_APP_PASSWORD`가 서비스 실행 계정에 설정되어 있는지 확인합니다.

### heartbeat 또는 정책 조회가 실패하는 경우

- `ControlPlaneUrl`이 HTTPS 주소인지 확인합니다.
- `ControlPlaneApiKey`와 서버의 `MAILSHIELD_AGENT_API_KEY`가 일치하는지 확인합니다.
- 서버의 `/healthz` 응답을 확인합니다.
- 방화벽과 프록시가 해당 주소로의 HTTPS 연결을 허용하는지 확인합니다.

### 보안 경고가 표시되는 경우

현재 MailKit/MimeKit 보안 권고가 남아 있을 수 있습니다. 권고가 해결된 패키지 조합으로 재빌드하기 전에는 외부 고객에게 배포하지 마십시오.

## 8. 제거

관리자 PowerShell에서 실행합니다.

```powershell
Stop-Service MailShieldAgent
sc.exe delete MailShieldAgent
```

설치 디렉터리와 로컬 정책 캐시 삭제 여부는 조직의 보존 정책을 확인한 후 결정합니다.

## 9. 개인정보 보호 주의사항

- 메일 원문과 첨부파일을 일반 로그에 기록하지 않습니다.
- 주민등록번호, 카드번호, 계좌번호, 인증정보는 원문 공유를 금지합니다.
- API 키와 앱 비밀번호를 Git, `appsettings.json`, 스크린샷에 저장하지 않습니다.
- 상담이나 외부 분석으로 데이터를 전달할 때는 사용자·조직 동의를 먼저 받습니다.
