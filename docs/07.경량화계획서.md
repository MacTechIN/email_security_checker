## 2. 문제 요약

1. **onefile 패키징**이 가장 큰 디스크 부하다. 실행마다 106 MB를 임시 폴더에 풀고, 강제 종료 시 그대로 남는다. 프로세스도 2개가 된다.
2. **keyring**이 기동 시간의 절반과 6.5 MB를 차지한다. Windows 자격 증명 관리자 읽기·쓰기는 pywin32의 `win32cred` 직접 호출로 충분하다(pywin32는 이미 의존성).
3. **10 Hz 타이머**가 유휴 CPU 0.8%의 원인이다. 상주 앱은 유휴 시 0에 가까워야 한다.
4. **PIL + pystray**는 아이콘 6장을 그리기 위해 7 MB를 상주시킨다. 아이콘을 빌드 시 `.ico`로 만들어 두면 런타임 PIL이 필요 없다.
5. 메일마다 체크포인트를 즉시 디스크에 쓴다. 폭주 시(이메일 폭탄, 재시작 따라잡기 200건) 쓰기가 수백 회로 늘어난다.

## 3. 개선안과 시뮬레이션

시뮬레이션 근거: 1.5절 임포트별 증분(제거 시 그만큼 감소), 1.2절 기동 I/O(onedir는 추출 없음), 1.3절 스레드 CPU(타이머 주기 비례).

### 3.1 개선 항목

| # | 개선 | 방법 | 기대 효과 | 위험 | 규모 |
|---|---|---|---|---|---|
| A | onefile → onedir 패키징 | PyInstaller spec을 onedir로, Inno Setup이 폴더째 설치. 기동 시 `_MEI*` 잔재 자동 정리 | 기동 디스크 쓰기 106 MB → 0, 기동 7~11초 → 1~2초, 프로세스 2 → 1, 임시 폴더 누적 제거 | 설치 폴더 약 110 MB 상주(대신 임시 폴더 0). 설치기 변경 | 0.5일 |
| B | keyring 제거 → `win32cred` 직접 호출 | `CredRead/CredWrite/CredDelete`(제네릭 자격증명, 청크 저장 유지) | 임포트 −740 ms, 메모리 −6.5 MB, DLL 감소 | 기존 keyring 저장 항목을 읽어 옮기는 1회 마이그레이션 필요 | 0.5일 |
| C | UI 디스패처 타이머 완화 | 유휴 시 100 ms → 1,000 ms, 작업이 들어오면 `after(0)`으로 즉시 처리(워커가 큐에 넣을 때 `event_generate`로 깨움) | 유휴 CPU 0.8% → 0.1~0.2% | Tk 스레드 안전 규칙 준수 필요(측정으로 확인) | 0.5일 |
| D | 체크포인트·로그 쓰기 병합 | `state.json`은 5초 디바운스 + 종료 시 즉시, 로그 기본 레벨 WARNING(분석 결과는 DEBUG), 회전 2 MB × 3 | 메일당 디스크 쓰기 4~5회 → 1~2회, 폭주 시 수백 회 → 수 회 | 비정상 종료 시 최대 5초분 재처리(중복 알림 가능, 따라잡기 상한으로 제한) | 0.5일 |
| E | IDLE 주기 조정 | `idle_timeout` 기본 25초 → 60초(설정 가능), 세션 갱신 20분 유지 | 네트워크 왕복 폴더당 시간당 144회 → 60회 | 최악 탐지 지연 25초 → 60초 | 0.1일 |
| F | PIL·pystray 제거 → pywin32 `Shell_NotifyIcon` 직접 구현 | 빌드 시 아이콘 6장을 `.ico`로 생성, 런타임은 win32gui로 트레이 아이콘·메뉴 | 메모리 −7 MB, DLL 감소, 스레드 −1 | 트레이 구현 재작성(약 150줄), 메뉴·더블클릭·툴팁 회귀 검증 | 1.5일 |
| G | google-auth 지연 로드 유지·확인 | 이미 함수 안에서 임포트. OAuth 미사용 시 로드되지 않음을 테스트로 고정 | 앱 비밀번호 계정 −11.4 MB 보장 | 없음 | 0.1일 |
| H | 측정 스크립트 추가 | `tray/build/Measure-MailShieldTray.ps1`: 프로세스 수, WS/Private, 스레드 CPU, I/O, 임시 폴더, 기동 시간을 표로 출력 | 개선 전후 동일 기준 비교, 24시간 측정 재사용 | 없음 | 0.3일 |

### 3.3 하지 않는 것

- .NET 이식(2단계 계획)과는 별개의 작업이다. 여기서는 Python 앱을 그대로 두고 부하만 줄인다.
- 탐지 규칙·UI 기능 변경은 포함하지 않는다.
- Tk 자체 제거는 하지 않는다. 설정·사건·근거 창이 Tk에 의존하며, 대체 비용이 효과보다 크다.

### 3.4 실측 추가 (2026-09-11 저녁)

| 지표 | 현재 onefile | PyInstaller onedir(실측) | Nuitka standalone(실측) |
|---|---|---|---|
| 프로세스 수 | 2 | 1 | 1 |
| 기동(실행 → 첫 로그) | 10~11.5초 | 2.5초 | 1.1초 |
| 임시 폴더 추출 | 106 MB | 없음 | 없음 |
| 작업 세트 / 개인 메모리 | 121 / 56 MB | 107 / 48.6 MB | 157 / 44.5 MB |
| 폴더 크기 | exe 49 MB | 116 MB, 1,028파일 | 111 MB, 983파일 |
| 소스·바이트코드 포함 | .pyc 전부 포함 | .pyc 전부 포함 | 없음(C 컴파일) |

배포용은 소스 비노출 요구에 따라 Nuitka standalone으로 확정했다. 작업 세트가 큰 것은 컴파일된 코드가 메모리에 매핑되기 때문이며 실제 점유(개인 메모리)는 가장 작다. 나머지 경량화 항목(B~E, F)은 사용자 지시에 따라 보류한다.

| 단계 | 내용 | 검증 |

## 5. 확인 요청

- 1차(A~E, G, H)만 진행할지, 2차(F)까지 포함할지
- IDLE 주기 60초(최악 탐지 지연 60초) 허용 여부
- 로그 기본 레벨을 WARNING으로 낮추는 것(분석 결과 상세는 DEBUG로 이동, 문제 시 설정에서 켬) 허용 여부
