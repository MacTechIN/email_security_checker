# MailShield(메일쉴드) 기능 명세서

## 1. 문서 개요

### 1.1. 목적

본 문서는 MailShield의 사용자 및 관리자 기능, 처리 흐름, 기능별 요구사항, 수용 기준과 테스트 참조를 정의한다. MailShield의 핵심 목표는 이메일을 통해 외부로 빠져나갈 수 있는 개인정보와 중요정보를 사전에 탐지하고, 관리자에게 위험 사용자와 사건을 알려 신속한 대응을 지원하는 것이다.

### 1.2. 적용 범위

- 이메일 계정 연결 및 권한 인증
- 이메일 주소 기반 DNS·자동설정 탐지와 공개 인프라 진단
- 수신 이메일의 피싱·악성코드·발신자 위변조 분석
- 발신 이메일의 개인정보·기밀정보·오발송 위험 분석
- 등록된 프로그램이 생성한 보호 대상 파일의 이메일 첨부·전송 이력 추적
- 첨부파일, URL 및 계정 유출 여부 점검
- 사용자 진단 결과와 행동 지침 제공
- 관리자 위험 현황, 알림, 정책 및 조치 관리
- 탐지·알림·조치 감사 이력 관리

### 1.3. 사용자 역할

| 역할 ID | 역할 | 주요 권한 |
|---|---|---|
| ROLE-USER | 일반 사용자 | 본인 계정 연결, 분석 실행, 본인 결과 확인, 경고 확인 및 조치 |
| ROLE-MANAGER | 관리자 | 조직 위험 현황 확인, 사건 검토, 승인·차단·해제, 사용자 통보 |
| ROLE-ADMIN | 시스템 관리자 | 조직 정책, 연동, 권한, 보존 기간 및 알림 채널 설정 |

## 2. UI 및 프로세스 흐름

### 2.0. Windows 상주 실행 흐름

`Windows 시작` → `에이전트 상태 확인` → `메일 서버 연결·IDLE 대기` → `새 메일 이벤트 수신` → `로컬 분석` → `Windows/관리자 알림` → `사건 이력 저장`

- 개발·개인용 실행: `realtime_email_monitor.pyw`를 더블클릭해 콘솔 없는 백그라운드 실행
- 운영 실행: Windows Service가 감시 작업자를 자동 시작·복구하고 WPF 트레이 앱이 사용자 알림을 표시
- `.pyw`는 콘솔 창을 숨기는 실행 방식일 뿐 서비스 복구·권한 통제·자동 업데이트를 제공하지 않으므로 운영 배포 방식으로 단독 사용하지 않는다.

### 2.1. 일반 사용자 진단 흐름

`메일 주소 입력` → `DNS·메일 환경 자동 탐지` → `공개 인프라 진단` → `환경별 인증 및 동의` → `실시간 분석` → `종합 보고서` → `환경별 대응 및 상담 연결`

1. 사용자가 이메일 주소를 입력한다.
2. 시스템이 DNS와 표준 자동설정 정보를 조회해 공급자·연결 후보와 공개 보안 상태를 식별한다.
3. 사용자가 탐지된 환경에 맞는 방식으로 인증하고 진단 범위를 선택한다.
4. 시스템이 단계별 분석 상태와 검사 로그를 표시한다.
5. 서버, 수신 메일, 발신 유출 및 계정 분야의 결과와 환경별 대응책을 제공한다.

### 2.2. 발송 전 위험 감시 흐름

`메일 작성/발송 시도` → `본문·수신자·첨부파일 분석` → `위험도 판정` → `허용/경고/보류/차단` → `사용자 및 관리자 알림` → `조치 이력 저장`

1. 사용자가 메일 발송을 시도한다.
2. 시스템이 외부 수신자, 민감정보, 첨부파일 및 비정상 발송 패턴을 분석한다.
3. 조직 정책과 위험 점수에 따라 정상 발송, 사용자 경고, 관리자 승인 보류 또는 차단을 결정한다.
4. 고위험 사건은 관리자에게 알리고 탐지 및 조치 내용을 감사 이력에 저장한다.

### 2.3. 관리자 대응 흐름

`관리자 대시보드` → `위험 사용자/사건 목록` → `사건 상세` → `승인/차단/사용자 확인 요청` → `처리 완료 및 감사 기록`

## 3. 공통 상태 및 위험 등급

### 3.1. 위험 등급

| 등급 | 점수 예시 | 의미 | 기본 처리 |
|---|---:|---|---|
| 안전(Safe) | 0~29 | 특별한 위험이 없거나 영향이 낮음 | 정상 처리 |
| 주의(Caution) | 30~59 | 사용자의 확인이 필요한 잠재 위험 | 경고 후 진행 가능 |
| 위험(High) | 60~79 | 정보 유출 또는 공격 가능성이 높음 | 발송 보류 및 관리자 알림 |
| 긴급(Critical) | 80~100 | 즉각적인 피해가 예상되는 중대 위험 | 차단 및 긴급 알림 |

> 실제 점수 구간과 처리 정책은 조직별로 설정할 수 있어야 한다. 점수만으로 사용자를 위험 인물로 단정하지 않으며, 탐지 근거와 관리자 검토 결과를 함께 기록한다.

### 3.2. 사건 처리 상태

`탐지됨` → `검토 중` → `사용자 확인 대기` 또는 `관리자 승인 대기` → `조치 완료` 또는 `오탐 처리`

## 4. 상세 기능 명세(SRS)

### 4.1. 계정 및 진단 기능

#### FN-100 이메일 입력 및 서버 자동 탐지

- **설명:** 이메일 형식을 검증하고 도메인을 추출한 뒤 MX·TXT·SRV, 표준 Autoconfig/Autodiscover 및 검증된 ISP 메타데이터를 조회한다.
- **출력:** 공급자 후보와 신뢰도, 공개 보안 상태, 인증 방식 및 안전한 IMAP 연결 후보
- **수용 기준:**
  - 주소만 입력한 상태에서는 공개 정보만 조회하고 메일함 접근을 시도하지 않는다.
  - MX 호스트를 IMAP 호스트로 단순 변환하지 않는다.
  - 자동설정 후보의 TLS 인증서와 호스트 일치 여부를 검증한다.
  - 내부망·루프백·링크 로컬 주소 연결을 차단해 SSRF를 방지한다.
  - 공급자를 식별하지 못하면 검증 가능한 수동 설정을 제공한다.
- **테스트 참조:** TC-FN100-01~12, DATA-DNS-01~12, SEC-SSRF-01~04

#### FN-101 계정 연결 및 인증

- **설명:** Google·Microsoft 등 지원 공급자는 OAuth 2.0을 사용하고 일반 IMAP은 앱 비밀번호 또는 공급자 전용 자격증명을 우선 사용한다. 일반 계정 비밀번호 입력은 명시적으로 허용된 제한 환경에서만 제공한다.
- **입력:** 이메일 계정, 인증 동의, 조직 식별정보
- **처리:** 최소 권한 요청, 인증 토큰 암호화 저장, 만료·철회 상태 관리
- **출력:** 연결 성공 여부, 연결 계정, 허용된 권한, 오류 안내
- **예외:** 인증 취소, 권한 부족, 토큰 만료, 공급자 장애
- **수용 기준:**
  - 사용자가 동의한 권한만 요청하고 화면에 수집 목적을 표시한다.
  - 평문 인증과 유효하지 않은 TLS 인증서 연결을 거부한다.
  - 인증 실패 시 비밀번호나 토큰 원문을 로그에 남기지 않는다.
  - 연결 해제 시 이후 접근을 중단하고 토큰을 폐기한다.
- **테스트 참조:** TC-FN101-01~05, SEC-AUTH-01~03

#### FN-102 진단 범위 선택

- **설명:** 최근 50개, 최근 100개 또는 특정 기간을 진단 범위로 선택한다.
- **입력:** 진단 개수 또는 시작·종료 일시
- **출력:** 예상 검사량과 분석 시작 확인
- **수용 기준:**
  - 종료일이 시작일보다 빠른 기간은 제출할 수 없다.
  - 계정 접근 범위를 초과한 요청에는 명확한 안내를 제공한다.
- **테스트 참조:** TC-FN102-01~04

#### FN-103 실시간 분석 진행 표시

- **설명:** 연결 확인, 헤더 검증, 본문·URL 분석, 첨부파일 검사, 유출 위험 분석의 진행 상태를 표시한다.
- **출력:** 전체 진행률, 현재 단계, 검사 건수, 비식별화된 실시간 로그, 취소·재시도 상태
- **수용 기준:**
  - 진행률은 완료된 작업량을 기준으로 계산하며 완료 전 100%를 표시하지 않는다.
  - 로그에는 이메일 본문, 인증정보 및 전체 개인정보를 노출하지 않는다.
  - 오류가 발생하면 완료로 위장하지 않고 실패 단계와 재시도 방법을 표시한다.
- **테스트 참조:** TC-FN103-01~05, SEC-LOG-01

#### FN-104 IMAP 실시간 폴더 감시

- **설명:** IMAP IDLE 지원 공급자에서는 폴더별 독립 연결을 유지해 변경 알림을 수신한다. 미지원 서버는 공급자 정책을 준수하는 증분 동기화로 대체한다.
- **감시 대상:** `INBOX`, SPECIAL-USE 플래그 또는 공급자 설정으로 찾은 `Sent`, 관리자가 승인한 추가 폴더
- **처리:** 폴더 탐색 → UIDVALIDITY·마지막 UID 저장 → IDLE → 변경 알림 → UID 증분 FETCH → 분석 큐 → IDLE 갱신·재연결
- **수용 기준:**
  - 감시 폴더마다 독립 연결 또는 동등한 비동기 세션을 사용한다.
  - 공급자의 동시 연결 수와 IDLE 유지 제한을 설정으로 관리한다.
  - 연결 끊김, 인증 만료, 절전 복귀 후 지수 백오프로 재연결한다.
  - UID 기반으로 누락분을 보충하고 중복 사건 생성을 방지한다.
  - UIDVALIDITY 변경 시 체크포인트를 안전하게 재구성한다.
  - `Sent` 감시는 발송 후 탐지이며 발송 전 차단으로 표시하지 않는다.
- **테스트 참조:** TC-FN104-01~12, INT-IDLE-01~10, REL-IMAP-01~08

#### FN-105 Windows 백그라운드 에이전트 실행

- **설명:** 감시 엔진을 Windows 백그라운드 프로세스로 실행하고 트레이 또는 Windows 알림으로 상태와 위험 이벤트를 전달한다.
- **개발 실행:** `.pyw` 파일 더블클릭 또는 `pythonw.exe` 실행
- **운영 실행:** 서명된 .NET Windows Service + 제한 권한 트레이 UI
- **수용 기준:**
  - 콘솔 창 없이 감시가 유지되고 프로세스 종료·예외가 중앙 상태에 보고된다.
  - Windows 재부팅과 네트워크 단절 후 자동 재연결한다.
  - 사용자 알림에는 개인정보 원문과 첨부파일 원본을 포함하지 않는다.
  - 트레이에서 일시 중지·재개·상태 확인을 수행할 수 있고 관리자 정책을 우선한다.
  - 단일 에이전트가 중복 실행되어 IMAP 연결을 과도하게 생성하지 않는다.
- **테스트 참조:** TC-FN105-01~10, REL-AGENT-01~08, UI-TRAY-01~05

### 4.2. 이메일 보안 분석 기능

#### FN-200 메일 서버 인프라 진단

- **설명:** 인증 전에는 공개 DNS 정책을, 인증 또는 명시적 허용 후에는 확인된 서비스 엔드포인트의 TLS 상태를 진단한다.
- **출력:** MX, SPF, DMARC, MTA-STS, TLS-RPT, 인증서 유효성, TLS 지원과 인프라 점수
- **수용 기준:**
  - DMARC의 `none`, `quarantine`, `reject`, 설정 부재와 조회 실패를 구분한다.
  - DKIM은 selector를 무차별 탐색하지 않고 실제 서명 메일 또는 제공된 selector로 검증한다.
  - 제3자 서버를 대상으로 공격적 포트 스캔이나 취약점 공격을 수행하지 않는다.
- **테스트 참조:** TC-FN200-01~10, DATA-DNS-01~12, SEC-SSRF-01~04

#### FN-201 헤더 및 발신자 위변조 검증

- **설명:** SPF, DKIM, DMARC 결과와 From, Return-Path 및 Received 체인을 분석하여 발신자 위변조 가능성을 판정한다.
- **출력:** 인증별 성공 여부, 불일치 근거, 위변조 위험 점수
- **수용 기준:**
  - SPF·DKIM·DMARC의 성공, 실패, 미설정, 확인 불가를 구분한다.
  - 전달 및 메일링리스트 환경을 고려하고 단일 실패만으로 악성으로 확정하지 않는다.
  - 사용자가 이해할 수 있는 설명과 원본 기술 정보를 분리해 제공한다.
- **테스트 참조:** TC-FN201-01~07, DATA-HEADER-01~06

#### FN-202 AI 본문 및 URL 분석

- **설명:** AI 모델과 규칙 기반 엔진을 이용하여 긴급성 조성, 금융기관 사칭, 자격증명 요구, 비정상 문맥 및 피싱 가능성을 분석한다. 표시 문자열과 실제 URL 불일치, 단축 URL, 유사 도메인과 타이포스쿼팅을 탐지한다.
- **출력:** 위험 점수(0~100), 탐지 사유, 의심 문장·URL, 모델 및 규칙 버전
- **수용 기준:**
  - AI 판정에는 위험 근거를 최소 한 개 이상 제공한다.
  - AI 호출 실패 시 규칙 기반 결과를 제공하고 부분 분석임을 표시한다.
  - 외부 AI 전송 전에 불필요한 개인정보를 제거하거나 마스킹한다.
  - 프롬프트 인젝션 문구가 포함된 이메일을 시스템 명령으로 실행하지 않는다.
- **테스트 참조:** TC-FN202-01~09, AI-SAFE-01~04, DATA-URL-01~08

#### FN-203 첨부파일 무결성 및 악성 여부 분석

- **설명:** 파일명, 실제 MIME 형식, 다중 확장자, 매크로, 압축파일 및 SHA-256 해시 평판을 검사한다.
- **출력:** 파일별 위험도, 탐지 근거, 해시 조회 결과, 검사 가능 여부
- **수용 기준:**

- **입력:** 프로그램명, 실행 파일 경로, 게시자 서명, 생성 폴더, 확장자 목록, 허용 수신자·도메인, 처리 정책
- **출력:** 정책 ID, 버전, 적용 장치, 동기화 상태
- **수용 기준:**

  - 정책 변경자, 변경 시각과 이전 버전을 기록한다.
  - 광범위한 와일드카드 규칙은 예상 영향 확인 후에만 배포한다.

- **출력:** 일치 신뢰도, 이름·확장자 변경 여부, 외부 전송 여부, 사건 ID, 허용·경고·보류·차단 결과
- **수용 기준:**
  - 등록 확장자의 정상 첨부, 이름 변경, 이중 확장자 및 압축 컨테이너 포함 테스트를 구분한다.
  - 파일 해시가 동일하면 파일명이 변경되어도 동일 파일 후보로 연결한다.
  - 생성 이벤트가 없거나 파일 접근 권한이 부족하면 출처를 확정하지 않고 `확인 불가`로 기록한다.
  - 발송 시도와 실제 발송 완료를 구분하며 중복 이벤트를 하나의 사건으로 묶는다.
  - 중앙 서버에는 기본적으로 원본 파일을 업로드하지 않고 최소 메타데이터와 마스킹 근거만 보낸다.

#### FN-211 개인정보 유출 상시 감시

  - 고유식별정보: 주민등록번호, 외국인등록번호, 여권번호, 운전면허번호
  - 결제정보: 신용·체크카드 번호, 유효기간, CVC 의심 조합
  - 금융정보: 국내외 계좌번호, 은행명, 예금주, 송금·거래내역
  - 개인신상: 이름, 주소, 생년월일, 전화번호, 이메일, 가족관계
  - 민감정보: 건강·의료, 인사·급여, 학력·경력, 위치 및 생체정보
  - 인증정보: 아이디, 비밀번호, OTP·인증번호, API 키, 비밀키 및 접근 토큰

  - 카드번호는 Luhn 체크섬과 주변 결제 문맥을, 주민등록번호는 형식·날짜 유효성·문맥을 함께 평가한다.
  - 계좌번호는 구분자 정규화, 은행별 형식 후보와 은행·예금주 문맥을 결합하며 패턴만으로 확정하지 않는다.
  - 서로 다른 개인정보가 결합되거나 다량 포함된 경우 위험 점수를 가중한다.
  - 암호화·손상·미지원 첨부파일은 안전으로 처리하지 않고 `검사 불가`로 표시한다.
  - 탐지값 원문은 UI·알림·로그에서 마스킹한다.
  - 고유식별정보와 금융정보 원문은 기본적으로 중앙 서버에 저장하지 않는다.
  - 사용자, 기간, 유형, 수신 도메인과 처리 결과별 통계를 제공한다.

  - 동일 해시 또는 캠페인의 반복 사건을 묶어 알림 폭주를 방지한다.

### 4.5. 관리자 기능

- **알림 필드:** 사건 ID, 사용자, 발생 시각, 위험 유형, 등급, 마스킹된 근거, 권장 조치, 상세 링크
- **수용 기준:**

  - 중복 사건은 정책에 따라 묶어 알림 폭주를 방지한다.
  - 실패한 알림은 재시도하며 최종 실패를 기록한다.
- **테스트 참조:** TC-FN402-01~09, INT-NOTIFY-01~05

#### FN-403 사건 상세 및 관리자 조치

- **설명:** 관리자가 탐지 근거와 관련 이력을 확인하고 승인, 차단, 사용자 확인 요청, 오탐 또는 사고 확정으로 처리한다.
- **수용 기준:**
  - 모든 상태 변경에 관리자와 사유를 기록한다.
  - 이미 처리된 사건의 동시 수정 충돌을 방지한다.
  - 오탐 처리 결과를 정책 개선용 데이터로 구분해 저장한다.
- **테스트 참조:** TC-FN403-01~08, SEC-AUDIT-04~06

#### FN-404 조직 보안 정책 관리

- **설명:** 위험 점수 기준, 내부 도메인, 민감정보 규칙, 허용 목록, 차단 목록, 발송 제어 및 알림 정책을 관리한다.
- **수용 기준:**
  - 정책 저장 전 예상 영향을 검토할 수 있다.
  - 정책 변경자를 기록하고 이전 버전으로 복구할 수 있다.
  - 권한이 있는 관리자만 정책을 변경할 수 있다.
- **테스트 참조:** TC-FN404-01~09, SEC-RBAC-06~08

#### FN-405 감사 이력 및 보고서

- **설명:** 탐지, 조회, 알림, 승인, 차단, 정책 변경 및 데이터 내보내기 이력을 검색·내보내기할 수 있다.
- **수용 기준:**
  - 감사 기록에 사건 ID, 행위자, 행위, 시각, 결과를 포함한다.
  - 일반 관리자에게 로그 임의 수정·삭제 권한을 제공하지 않는다.
  - 내보낸 파일의 개인정보는 권한과 정책에 따라 마스킹한다.
- **테스트 참조:** TC-FN405-01~07, SEC-AUDIT-07~10

### 7.3. 기능 완료 조건(Definition of Done)

각 기능은 다음 조건을 모두 충족해야 완료로 판단한다.

- 기능 명세의 수용 기준을 모두 통과한다.
- 정상, 실패, 경계값 및 권한 오류 테스트가 작성되어 있다.
- 관련 단위·통합·E2E 테스트가 자동화되거나 수동 절차로 문서화되어 있다.
- 민감정보가 화면, 로그, 오류 메시지 및 외부 연동에 불필요하게 노출되지 않는다.
- 보안 및 개인정보 영향이 검토되었다.
- 사용자 안내와 관리자 감사 이력이 요구사항에 맞게 제공된다.
- 테스트 결과가 요구사항 ID와 양방향으로 추적 가능하다.

## 8. 요구사항 추적성 기준

개발 티켓, 소스 변경, 테스트 케이스 및 결함에는 관련 기능 ID를 기록한다. 예를 들어 민감정보 탐지 개발 티켓은 `FN-205`, 테스트는 `TC-FN205-*`, 테스트 데이터는 `DATA-DLP-*`로 연결한다. 요구사항이 변경되면 관련 테스트와 사용자 안내 문서도 함께 검토한다.

## 9. 범위 제외 및 추후 검토

- 사용자의 동의나 적법한 조직 정책 없이 개인 이메일 전체를 무제한 감시하는 기능
- 이메일 주소만으로 인증 없이 본문이나 첨부파일을 읽는 기능

- 제3자 서버에 대한 공격적 포트 스캔과 취약점 공격
- 탐지 결과만으로 사용자를 자동 징계하거나 위험 인물로 확정하는 기능
- 첨부파일을 실제 사용자 환경에서 실행하는 동적 분석
- 법률·수사·금융 피해 보상을 대신하는 기능
- 외부 상담기관에 사용자 데이터를 자동 전송하는 기능
