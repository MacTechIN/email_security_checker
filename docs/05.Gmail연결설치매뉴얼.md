# Gmail 연결 설치 매뉴얼

이 문서는 MailShield 개발용 PC에서 Gmail 계정을 IMAP으로 연결하기까지의 모든 준비 과정을 처음부터 다시 수행할 수 있도록 정리한 것입니다. Google 계정 설정, Google Cloud Console 설정, PC 설치, 연결 테스트, 문제 해결 순서로 구성되어 있습니다.

연결 방식은 두 가지입니다.

| 방식 | 권장 여부 | 준비물 | 사용 스크립트 |
| --- | --- | --- | --- |
| OAuth 2.0 (브라우저 로그인) | **권장** | Google Cloud 프로젝트, `credentials.json` | `code_snipt/test_gmail_oauth_imap.py` |
| 앱 비밀번호 | 보조 | 2단계 인증, 16자리 앱 비밀번호 | `code_snipt/test_gmail_imap.py` |

MailShield 설계 문서(`docs/02.개발계획서.md`)는 Google 계정에 OAuth를 우선 적용하도록 정하고 있습니다. 앱 비밀번호는 OAuth 설정이 불가능한 경우의 대안입니다.

---

## 1. 사전 확인

### 1.1 계정 종류 확인

- 개인 Gmail(`@gmail.com`)이면 본인이 모든 설정을 직접 할 수 있습니다.
- Google Workspace(회사 도메인) 계정이면 관리자가 IMAP, 앱 비밀번호, 외부 OAuth 앱 사용을 허용해야 합니다. 관리자 콘솔 설정 없이는 아래 절차가 실패할 수 있습니다.

### 1.2 PC 준비물

| 항목 | 확인 방법 | 기대 결과 |
| --- | --- | --- |
| Python 3.11 이상 | `python --version` | `Python 3.1x.x` 출력 |
| pip | `python -m pip --version` | 버전 출력 |
| 기본 브라우저 | Chrome, Edge 등 | Google 로그인 가능 |
| 네트워크 | 993/TCP, 443/TCP 아웃바운드 | 회사 방화벽이 IMAP을 막지 않아야 함 |

### 1.3 저장소 위치

모든 명령은 저장소 루트에서 실행합니다.

```powershell
Set-Location "C:\Users\이상진\Documents\email_checker"
```

## 2. Gmail 계정 설정 (Google 웹)

### 2.1 IMAP 활성화

1. https://mail.google.com 접속 후 로그인
2. 오른쪽 위 톱니바퀴 아이콘 → **모든 설정 보기**
3. **전달 및 POP/IMAP** 탭
4. **IMAP 액세스** 항목에서 **IMAP 사용** 선택
5. 아래쪽 **변경사항 저장**

> 2024년 이후 만들어진 계정은 IMAP이 기본 활성화되어 있어 이 항목이 표시되지 않을 수 있습니다. 항목이 없으면 이미 활성화된 것으로 보고 다음 단계로 넘어갑니다.

### 2.2 2단계 인증 활성화 (앱 비밀번호 방식에만 필수)

1. https://myaccount.google.com/security 접속
2. **Google에 로그인하는 방법** → **2단계 인증**
3. 안내에 따라 휴대전화 번호 또는 Google 인증 앱 등록
4. 완료 후 상태가 **사용 중**인지 확인

OAuth 방식만 사용할 경우 이 단계는 필수가 아니지만 계정 보안을 위해 켜 두는 것을 권장합니다.

## 3. OAuth 2.0 설정 (Google Cloud Console)

이 절차는 한 번만 수행하면 됩니다. 결과물은 `credentials.json` 파일 하나입니다.

### 3.1 프로젝트 생성

1. https://console.cloud.google.com 접속, Gmail 계정으로 로그인
2. 처음 접속이면 서비스 약관 동의
3. 상단 프로젝트 선택 드롭다운 → **새 프로젝트**
4. 프로젝트 이름: `mailshield-dev` (임의)
5. **만들기** → 생성 완료 후 해당 프로젝트 선택

### 3.2 Gmail API 사용 설정

1. 왼쪽 메뉴 → **API 및 서비스** → **라이브러리**
2. 검색창에 `Gmail API` 입력
3. **Gmail API** 선택 → **사용** 버튼

> IMAP XOAUTH2 인증 자체는 Gmail API 활성화 없이도 동작하지만, 동의 화면에서 `https://mail.google.com/` 범위를 등록하려면 Gmail API가 활성화되어 있어야 합니다.

### 3.3 OAuth 동의 화면 구성

Google Cloud Console은 2025년부터 OAuth 설정을 **Google Auth Platform** 메뉴로 옮겼습니다. 화면 이름이 다를 수 있으니 두 경로를 함께 적습니다.

- 새 경로: 왼쪽 메뉴 → **Google Auth Platform** (또는 https://console.cloud.google.com/auth/overview)
- 이전 경로: **API 및 서비스** → **OAuth 동의 화면**

설정 순서:

1. **시작하기** (또는 **동의 화면 구성**) 클릭
2. **앱 정보**
   - 앱 이름: `MailShield Dev`
   - 사용자 지원 이메일: 본인 Gmail 주소
3. **대상(Audience)**: **외부(External)** 선택
   - 개인 Gmail은 **내부** 선택이 불가능합니다. 외부를 선택하고 테스트 모드로 사용합니다.
4. **연락처 정보**: 본인 Gmail 주소
5. 정책 동의 체크 후 **만들기**

### 3.4 테스트 사용자 추가

앱을 Google 심사에 제출하지 않고 사용하려면 로그인할 계정을 테스트 사용자로 등록해야 합니다.

1. **Google Auth Platform** → **대상(Audience)** (이전 경로: OAuth 동의 화면 → 테스트 사용자)
2. **테스트 사용자** 섹션 → **+ 사용자 추가**
3. 연결할 Gmail 주소 입력 (예: `wooriszhome@gmail.com`)
4. **저장**

> 테스트 사용자로 등록하지 않으면 로그인 시 **"403 access_denied: 이 앱은 Google에서 확인하지 않았습니다"** 또는 **"앱이 테스트 중이며 개발자가 승인한 테스터만 액세스할 수 있습니다"** 오류가 발생합니다.

### 3.5 범위(Scope) 등록

1. **Google Auth Platform** → **데이터 액세스(Data Access)** (이전 경로: OAuth 동의 화면 → 범위)
2. **범위 추가 또는 삭제**
3. 목록에서 다음 범위를 체크하거나 직접 입력:

   ```text
   https://mail.google.com/
   ```

4. **업데이트** → **저장**

이 범위는 **제한된 범위(restricted scope)** 로 분류됩니다. 테스트 모드에서는 테스트 사용자에 한해 심사 없이 사용할 수 있으며, 로그인 시 "확인되지 않은 앱" 경고 화면이 표시되는 것은 정상입니다.

### 3.6 OAuth 클라이언트 ID 생성

1. **Google Auth Platform** → **클라이언트(Clients)** (이전 경로: API 및 서비스 → 사용자 인증 정보 → + 사용자 인증 정보 만들기 → OAuth 클라이언트 ID)
2. **+ 클라이언트 만들기**
3. 애플리케이션 유형: **데스크톱 앱**
   - 반드시 데스크톱 앱을 선택합니다. 웹 애플리케이션을 선택하면 리디렉션 URI 오류가 발생합니다.
4. 이름: `MailShield Desktop Test`
5. **만들기**
6. 생성 완료 팝업에서 **JSON 다운로드** 클릭
   - 팝업을 닫았다면 클라이언트 목록 오른쪽 다운로드 아이콘으로 다시 받을 수 있습니다.

다운로드된 파일 이름은 `client_secret_XXXXXXXX.apps.googleusercontent.com.json` 형태입니다.

### 3.7 credentials.json 배치

다운로드한 파일을 다음 경로에 **정확히 이 이름으로** 복사합니다.

```text
C:\Users\이상진\Documents\email_checker\code_snipt\credentials.json
```

PowerShell 예시 (다운로드 파일 이름은 실제 이름으로 바꿉니다):

```powershell
Copy-Item "$env:USERPROFILE\Downloads\client_secret_*.json" `
  "C:\Users\이상진\Documents\email_checker\code_snipt\credentials.json"
```

배치 확인:

```powershell
Test-Path "C:\Users\이상진\Documents\email_checker\code_snipt\credentials.json"
```

`True`가 출력되어야 합니다.

> `credentials.json`과 `token.json`은 `.gitignore`에 등록되어 있어 Git에 커밋되지 않습니다. 절대로 이 파일을 다른 사람에게 공유하거나 저장소에 강제로 추가하지 마십시오.

## 4. PC 설치 (Python 패키지)

저장소 루트에서 실행합니다.

```powershell
Set-Location "C:\Users\이상진\Documents\email_checker"
python -m pip install --upgrade pip
python -m pip install -r .\code_snipt\requirements-realtime.txt
```

설치되는 패키지:

| 패키지 | 용도 |
| --- | --- |
| `google-auth` | OAuth 토큰 관리 |
| `google-auth-oauthlib` | 브라우저 로그인 흐름 |
| `imapclient` | 실시간 IMAP IDLE 감시 프로토타입 |
| `win10toast` | Windows 알림 (Windows 전용) |

설치 확인:

```powershell
python -c "import google.oauth2.credentials, google_auth_oauthlib, imapclient; print('deps OK')"
```

`deps OK`가 출력되면 정상입니다. `ModuleNotFoundError`가 나오면 위 pip 명령을 다시 실행합니다.

가상환경을 사용하는 경우:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r .\code_snipt\requirements-realtime.txt
```

## 5. 연결 테스트

### 5.1 OAuth 방식 (권장)

```powershell
Set-Location "C:\Users\이상진\Documents\email_checker\code_snipt"
$env:MAILSHIELD_GMAIL_ADDRESS = "wooriszhome@gmail.com"
python .\test_gmail_oauth_imap.py
```

진행 과정:

1. 기본 브라우저가 자동으로 열리고 Google 로그인 화면이 표시됩니다.
2. 연결할 Gmail 계정을 선택합니다.
3. **"Google에서 확인하지 않은 앱입니다"** 경고가 나오면 **고급** → **MailShield Dev(안전하지 않음)로 이동** 을 클릭합니다. 본인이 만든 테스트 앱이므로 정상입니다.
4. 권한 요청 화면에서 **계속** (또는 **허용**)
5. "인증 절차가 완료되었습니다. 이 창을 닫아도 됩니다" 메시지 후 브라우저를 닫습니다.
6. 터미널에 다음이 출력되면 성공입니다.

   ```text
   [성공] OAuth/XOAUTH2 Gmail 인증, INBOX=OK
   ```

성공하면 `code_snipt/token.json`이 생성됩니다. 이후 실행에서는 브라우저 로그인 없이 이 토큰을 재사용하며, 만료되면 자동 갱신됩니다.

> 테스트 모드 앱의 리프레시 토큰은 **7일** 후 만료됩니다. 7일 후 `invalid_grant` 오류가 나오면 `token.json`을 삭제하고 다시 실행해 브라우저 로그인을 반복하면 됩니다. 이 제한을 없애려면 동의 화면을 **프로덕션**으로 게시해야 하며, 제한된 범위를 사용하므로 Google 심사가 필요합니다.

### 5.2 앱 비밀번호 방식 (보조)

#### 앱 비밀번호 발급

1. 2단계 인증이 켜져 있어야 합니다 (2.2 참조).
2. https://myaccount.google.com/apppasswords 접속
3. 앱 이름 입력: `MailShield` → **만들기**
4. 화면에 표시되는 16자리 비밀번호를 복사합니다. 공백 포함 여부는 상관없습니다. 스크립트가 자동으로 제거합니다.
5. 이 화면을 닫으면 비밀번호를 다시 볼 수 없습니다. 분실 시 삭제 후 새로 만듭니다.

> `apppasswords` 페이지가 열리지 않거나 "이 설정은 계정에서 사용할 수 없습니다"가 표시되면 2단계 인증이 꺼져 있거나, Passkey 전용 계정이거나, Workspace 관리자가 앱 비밀번호를 차단한 것입니다.

#### 테스트 실행

```powershell
Set-Location "C:\Users\이상진\Documents\email_checker\code_snipt"
$env:MAILSHIELD_GMAIL_ADDRESS = "wooriszhome@gmail.com"
$env:MAILSHIELD_GMAIL_APP_PASSWORD = "여기에 발급받은 16자리 앱 비밀번호"
python .\test_gmail_imap.py
```

> 세 번째 줄의 따옴표 안에는 Google 화면에서 복사한 실제 16자리 영문을 넣어야 합니다. 안내 문구를 그대로 두고 실행하면 `[AUTHENTICATIONFAILED] Invalid credentials` 오류가 납니다.

환경변수를 생략하면 스크립트가 주소와 비밀번호를 직접 물어봅니다. 비밀번호 입력은 화면에 표시되지 않습니다.

성공 출력 예:

```text
imap.gmail.com:993 TLS 연결 중...
IMAP capabilities: ...
[성공] Gmail IMAP 인증
[성공] INBOX: 최신 메일
       From: ...
       Subject: ...
       Date: ...
보낸편지함 폴더: [Gmail]/Sent Mail
[성공] [Gmail]/Sent Mail: 최신 메일
Gmail 연결 테스트 완료
```

보낸편지함은 IMAP SPECIAL-USE `\Sent` 플래그로 찾습니다. 옛 메일 클라이언트가 만든 `Sent`라는 이름의 별도 라벨이 있어도 실제 Gmail 보낸편지함(`[Gmail]/Sent Mail`)이 선택됩니다.

### 5.3 실시간 감시 프로토타입 실행 (선택)

앱 비밀번호 방식으로만 동작합니다.

```powershell
Set-Location "C:\Users\이상진\Documents\email_checker\code_snipt"
$env:MAILSHIELD_EMAIL = "wooriszhome@gmail.com"
$env:MAILSHIELD_IMAP_HOST = "imap.gmail.com"
$env:MAILSHIELD_IMAP_PORT = "993"
$env:MAILSHIELD_APP_PASSWORD = "xxxx xxxx xxxx xxxx"
$env:MAILSHIELD_FOLDERS = "INBOX,[Gmail]/Sent Mail"
pythonw .\realtime_email_monitor.pyw
```

## 6. 문제 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `FileNotFoundError: credentials.json이 code_snipt 폴더에 없습니다.` | OAuth 클라이언트 JSON을 배치하지 않음 | 3.6~3.7 수행. 파일 이름이 정확히 `credentials.json`인지 확인 |
| `ModuleNotFoundError: No module named 'google'` 또는 `'imapclient'` | 패키지 미설치 또는 다른 Python 인터프리터 | 4장 pip 명령 실행. `where.exe python`으로 인터프리터 확인 |
| 브라우저: `403 access_denied` / "개발자가 승인한 테스터만 액세스" | 테스트 사용자 미등록 | 3.4에서 로그인 계정을 테스트 사용자로 추가 |
| 브라우저: `400 redirect_uri_mismatch` | 클라이언트 유형이 데스크톱 앱이 아님 | 3.6에서 **데스크톱 앱** 유형으로 클라이언트 재생성 |
| 브라우저: `Error 400: invalid_scope` | 범위 미등록 또는 Gmail API 미활성화 | 3.2, 3.5 확인 |
| `invalid_grant: Token has been expired or revoked` | 테스트 모드 토큰 7일 만료, 또는 비밀번호 변경 | `code_snipt\token.json` 삭제 후 재실행 |
| `[AUTHENTICATIONFAILED] Invalid credentials` (XOAUTH2) | 토큰 계정과 `MAILSHIELD_GMAIL_ADDRESS` 불일치 | 환경변수의 주소를 브라우저에서 로그인한 계정과 일치시킴. `token.json` 삭제 후 재실행 |
| `Application-specific password required` | 일반 계정 비밀번호를 앱 비밀번호 자리에 입력 | 5.2에서 16자리 앱 비밀번호 발급 후 사용 |
| `[ALERT] Please log in via your web browser` | Google이 로그인을 의심스러운 시도로 차단 | https://myaccount.google.com/notifications 에서 "본인입니다" 확인 후 재시도 |
| 앱 비밀번호 메뉴가 안 보임 | 2단계 인증 꺼짐, Passkey 전용, Workspace 정책 | 2.2 수행. Workspace이면 관리자에게 앱 비밀번호 허용 요청. 불가하면 OAuth 방식 사용 |
| `[실패] 네트워크/TLS 연결: timed out` | 993 포트 차단 | 다른 네트워크(휴대폰 테더링)에서 재시도. 회사망이면 방화벽 정책 확인 |
| 브라우저가 열리지 않음 | 기본 브라우저 미설정, 원격 데스크톱 환경 | 터미널에 출력된 URL을 브라우저 주소창에 직접 붙여넣기 |
| 한글 오류 메시지가 `����`로 깨짐 | 콘솔 코드페이지 문제 | `$env:PYTHONUTF8 = "1"` 설정 후 재실행. 동작에는 영향 없음 |

## 8. 보안 주의사항

- `credentials.json`, `token.json`, 앱 비밀번호는 계정 전체 메일에 접근할 수 있는 자격증명입니다. 채팅, 이메일, 스크린샷, Git 커밋에 포함하지 마십시오.
- 일반 Gmail 계정 비밀번호는 어떤 스크립트나 환경변수에도 입력하지 마십시오.
- 테스트가 끝난 개발용 PC를 폐기하거나 양도할 때는 7.1과 7.2를 먼저 수행합니다.
- 운영 제품에서는 이 문서의 개발용 클라이언트를 사용하지 않습니다. 별도 프로덕션 프로젝트와 Google 심사가 필요합니다.
