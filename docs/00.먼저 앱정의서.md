# MailShield(메일쉴드) 앱 정의서

## 1. 개요

- **서비스명:** MailShield(메일쉴드)
- **서비스 유형:** 공급자 독립형 이메일 보안 진단·상시 감시 및 관리자 알림 서비스
- **제품 형태:** Windows 메모리 상주형 에이전트 + 중앙 분석 서버 + 관리자 웹 콘솔
- **핵심 목적:** 특정 이메일 공급자에 종속되지 않고 이메일 도메인의 공개 보안 상태를 자동 진단한다. 사용자가 계정 접근을 승인한 경우에는 외부로 빠져나갈 수 있는 개인정보, 기밀정보, 계정정보 및 중요 문서를 사전에 탐지하고 관리자가 위험 사용자와 메일을 빠르게 확인하도록 한다.

MailShield는 주소에서 도메인을 추출하고 DNS, 표준 자동설정 및 공급자 정보를 이용해 메일 환경을 식별한다. 주소만 입력한 단계에서는 MX, SPF, DMARC, MTA-STS 등 공개 인프라만 진단하고, 메일 본문·첨부파일·발송 행위 분석은 명시적인 인증과 권한 동의 후 수행한다. 수신 위협뿐 아니라 정보 유출, 오발송, 위험한 첨부파일 전송 및 계정 탈취에 의한 비정상 발송을 지속적으로 감시한다.

## 2. 해결하려는 문제

이메일은 업무상 가장 많이 사용하는 정보 전달 수단이지만 다음과 같은 위험이 존재한다.

- 사용자가 개인정보나 회사 기밀이 포함된 내용을 외부로 잘못 발송할 수 있다.
- 수신자 자동완성이나 주소 오입력으로 중요 자료가 엉뚱한 사람에게 전달될 수 있다.
- 암호화되지 않은 민감 문서나 위험한 첨부파일이 외부로 전송될 수 있다.
- 피싱이나 계정 탈취로 인해 사용자 모르게 비정상 메일이 발송될 수 있다.
- 관리자는 사고가 발생하기 전까지 어떤 사용자가 위험한 행동을 하고 있는지 파악하기 어렵다.
- 기존 보안 제품의 경고는 전문 용어가 많아 일반 사용자와 관리자가 즉시 행동하기 어렵다.
- 메일 공급자마다 인증과 서버 설정이 달라 사용자가 정확한 연결 정보를 알기 어렵다.
- 자체 도메인의 SPF, DMARC 및 전송 암호화 상태가 취약해도 일반 사용자는 이를 확인하기 어렵다.

MailShield는 이러한 위험을 발송 전 또는 발생 초기에 탐지하여 사고를 예방하고, 관리자가 위험도를 기준으로 우선 대응할 수 있도록 돕는다.

## 3. 목표 사용자

### 3.1. 관리자

- 조직 내 이메일 보안을 담당하는 관리자
- 별도 보안팀이 없는 소규모 사업장의 대표 또는 IT 담당자
- 개인정보 및 중요 문서의 외부 유출 여부를 관리해야 하는 책임자

### 3.2. 일반 사용자

- Gmail, Microsoft 365, 국내 포털 또는 자체 도메인의 개인·업무용 이메일을 사용하는 임직원
- 이메일로 고객정보와 계약서 등을 자주 주고받는 소상공인 및 프리랜서
- 피싱, 오발송 및 개인정보 노출 위험에 취약한 사용자

## 4. 핵심 감시 대상

### 4.0. 메일 서버 인프라 위험

- MX 및 메일 공급자 구성 상태
- SPF와 DMARC 정책의 존재 여부 및 강도
- 외부에서 검증 가능한 메일 서버 TLS 인증서와 암호화 상태
- MTA-STS 및 TLS-RPT 등 전송 구간 보호 정책
- 표준 자동설정 정보의 누락 또는 안전하지 않은 연결 설정

MailShield는 이메일에서 발생할 수 있는 위험을 다음 영역으로 구분하여 감시한다.

### 4.1. 민감정보 유출 위험

- 주민등록번호, 외국인등록번호, 여권번호, 운전면허번호 등 고유식별정보 포함 여부
- 신용·체크카드 번호, 유효기간, CVC로 의심되는 결제정보 포함 여부
- 국내외 계좌번호, 은행명, 예금주, 송금·거래내역 등 금융정보 포함 여부
- 이름, 생년월일, 주소, 전화번호, 이메일, 가족관계 등 개인신상정보 포함 여부
- 건강·의료, 인사·급여, 학력·경력, 위치, 생체정보 등 민감정보 포함 여부
- 아이디, 비밀번호, 인증번호, API 키 및 접근 토큰 등 인증정보 포함 여부
- 비밀번호, API 키, 접근 토큰 등 계정·시스템 정보 포함 여부
- 회사 기밀, 계약정보 및 내부 전용 문구 포함 여부

탐지는 이메일 제목·본문뿐 아니라 지원 가능한 문서, 스프레드시트, PDF, 압축파일 내부까지 적용한다. 카드번호는 Luhn 검사, 주민등록번호와 계좌번호는 형식·문맥·기관 정보 등 복수 근거를 사용해 오탐을 줄인다. 탐지된 원문은 사용자 화면, 관리자 알림과 로그에서 마스킹한다.

### 4.2. 첨부파일 위험

- 개인정보 또는 중요 문서가 포함된 첨부파일
- 암호화되지 않은 민감 파일
- 실행파일, 매크로 문서 등 악성 가능성이 있는 파일
- 과도하게 큰 파일 또는 비정상적인 확장자의 파일
- 관리자가 등록한 업무 프로그램이 생성한 보호 대상 확장자 파일의 외부 전송
- 보호 대상 파일의 이름 변경, 확장자 위장 또는 압축 후 전송 시도

### 4.3. 수신자 및 발송 행위 위험

- 외부 이메일 주소로 중요정보를 발송하는 행위
- 수신자 오입력 또는 평소와 다른 수신자에게 보내는 행위
- 다수의 외부 수신자에게 대량 발송하는 행위
- 업무시간 외 발송, 짧은 시간 내 반복 발송 등 비정상적인 패턴

### 4.4. 계정 및 이메일 위협

- 피싱 또는 스미싱으로 의심되는 링크와 본문
- 발신자 및 이메일 헤더 위·변조
- 계정 탈취가 의심되는 비정상 발송
- 악성 첨부파일 및 의심스러운 외부 도메인

## 5. 주요 기능

### 5.0. 이메일 환경 자동 탐지 및 공개 진단

사용자가 이메일 주소를 입력하면 도메인을 추출해 MX·TXT·SRV 레코드, 표준 Autoconfig/Autodiscover 엔드포인트 및 검증된 공급자 메타데이터를 조회한다. 공급자 후보, 인증 방식과 안전한 IMAP 설정 후보를 제시하며 인증 전에도 공개 인프라를 진단한다. MX 호스트와 IMAP 호스트는 동일하다고 가정하지 않는다.

### 5.1. 공급자별 안전한 인증

지원 공급자는 OAuth 2.0을 우선 사용한다. 일반 IMAP은 앱 비밀번호 또는 공급자 전용 자격증명을 우선하며 일반 계정 비밀번호 수집은 기본 흐름에서 제외한다.

### 5.2. 이메일 위험 사전 탐지

이메일의 본문, 수신자, 첨부파일, 링크, 헤더 및 발송 패턴을 분석해 정보 유출과 보안 위협 가능성을 탐지한다. 가능한 경우 이메일이 외부로 발송되기 전에 사용자에게 경고하고, 정책에 따라 발송 보류 또는 관리자 확인 절차를 제공한다.

### 5.2.1. 등록 프로그램 생성 파일 추적

관리자는 보호할 프로그램, 실행 파일 서명·경로, 생성 폴더, 확장자 및 내부·외부 전송 정책을 등록할 수 있다. Windows 에이전트는 등록 프로그램이 생성한 파일의 경로, 확장자, 크기, 해시와 확인 가능한 생성 프로세스 정보를 로컬에서 연계한다. 해당 파일 또는 이름이 변경된 동일 파일이 메일에 첨부되면 발송 시도와 결과를 사건으로 기록하고 정책에 따라 경고, 보류 또는 차단한다. 원본 파일 내용은 기본적으로 중앙 서버에 저장하지 않는다.

### 5.3. 위험도 분류

탐지 결과를 **안전, 주의, 위험, 긴급** 단계로 구분한다. 위험 판단 근거와 예상 피해를 일반 사용자도 이해할 수 있는 표현으로 제공한다.

### 5.4. 관리자 대시보드

관리자는 다음 정보를 한눈에 확인할 수 있다.

- 현재 위험도가 높은 사용자
- 사용자별 위험 행위 횟수와 추세
- 최근 탐지된 고위험 이메일
- 위험 유형별 발생 현황
- 조치가 필요한 미처리 경고
- 조직 전체의 이메일 보안 상태

### 5.5. 실시간 관리자 알림

고위험 상황이 발생하면 관리자에게 즉시 알린다. 알림에는 사용자, 발생 시각, 수신자, 위험 유형, 위험도, 탐지 근거 및 권장 조치를 포함한다. 알림 채널은 서비스 내 알림을 기본으로 하며 향후 이메일, 문자 및 협업 도구 연동을 지원할 수 있다.

### 5.6. 환경별 사용자 경고 및 대응 안내

전문 보안 용어 대신 사용자가 지금 해야 할 행동을 안내한다. 예를 들어 수신자 재확인, 민감정보 삭제, 파일 암호화, 링크 제거, 비밀번호 변경 등의 구체적인 조치를 제공한다.

### 5.7. 이력 및 감사 기록

탐지 내용, 알림 발송, 사용자 확인, 관리자 조치 및 최종 처리 결과를 기록하여 사고 조사와 보안 정책 개선에 활용한다.

## 6. 핵심 가치

- **사전 예방:** 사고 이후의 확인이 아니라 발송 전 또는 초기 단계에서 위험을 발견한다.
- **플랫폼 독립성:** 특정 포털에 종속되지 않고 표준 프로토콜과 공급자별 커넥터를 조합한다.
- **단계적 진단:** 주소만으로 공개 인프라를 진단하고 동의 후 메일함과 발송 행위를 심층 분석한다.
- **관리자 중심 가시성:** 관리자가 누가 위험한지, 무엇이 위험한지, 무엇부터 처리해야 하는지 바로 알 수 있다.
- **쉬운 설명:** 복잡한 분석 결과를 위험도, 시각적 진행 상태 및 행동 지침으로 단순화한다.
- **우선순위 기반 대응:** 모든 이벤트를 동일하게 취급하지 않고 피해 가능성과 심각도에 따라 분류한다.
- **원클릭 대응:** 경고 확인부터 발송 보류, 사용자 안내, 사고 기록까지 빠르게 처리할 수 있도록 한다.
- **지속적인 개선:** 반복되는 위험 행동과 사용자별 패턴을 분석해 조직의 보안 정책과 교육에 활용한다.

## 7. 대표 사용자 흐름

1. 사용자가 이메일 주소를 입력한다.
2. MailShield가 DNS·자동설정 정보를 조회해 공급자와 공개 서버 보안을 진단한다.
3. 사용자가 환경에 맞는 방식으로 메일함 접근을 승인한다.
4. Windows 상주 에이전트가 수신자, 본문, 첨부파일, 링크, 헤더 및 발송 패턴을 분석한다.
5. 위험이 있으면 사용자에게 경고하고 고위험 사건은 관리자에게 알린다.
6. 관리자가 승인, 차단, 사용자 확인 요청 또는 사고 대응을 수행한다.
7. 모든 탐지와 조치 결과를 이력으로 저장한다.

## 8. 성공 기준

- 외부로 발송되기 전 탐지한 민감정보 및 중요 문서 건수
- 등록 프로그램 생성 파일의 외부 첨부·발송 탐지율과 차단·승인 이력
- 개인정보 포함 메일의 탐지·수정·차단 건수
- 수신·발신 메일에서 발견한 스팸, 피싱 및 악성코드 건수
- 고위험 이메일에 대한 관리자 알림 도달률과 평균 확인 시간
- 경고 후 사용자가 발송을 취소하거나 내용을 수정한 비율
- 반복적인 위험 행동을 보이는 사용자의 감소율
- 오탐으로 인해 정상 업무가 방해받는 비율
- 실제 정보 유출 및 이메일 보안 사고의 감소율

## 9. 운영 및 보호 원칙

- 이메일 내용은 위험 탐지에 필요한 최소 범위에서만 처리한다.
- 이메일 주소만으로는 공개 DNS·인프라 정보만 진단하며 메일함에 접근하지 않는다.
- 메일함 진단 전 사용자 인증과 명시적인 권한 동의를 받는다.
- 개인정보와 이메일 데이터는 전송 및 저장 과정에서 암호화한다.
- 고유식별정보·금융정보는 기본적으로 중앙 서버에 원문 저장하지 않고 유형, 건수, 마스킹 값과 탐지 근거만 기록한다.
- 관리자 권한을 역할별로 제한하고 모든 조회와 조치를 기록한다.
- 사용자 감시 목적과 수집 범위를 명확히 고지하고 관련 법률 및 조직 정책을 준수한다.
- 탐지 결과만으로 사용자를 단정하지 않으며, 관리자 검토와 소명 절차를 제공한다.
- 정상 업무를 과도하게 차단하지 않도록 위험도와 정책을 조직별로 조정할 수 있게 한다.

## 10. 한 문장 정의

> MailShield는 이메일 주소로 공급자와 공개 서버 보안을 자동 진단하고, 인증 후 Windows 상주 에이전트가 정보 유출과 비정상 발송을 감시하여 관리자가 위험 사용자와 사건에 즉시 대응하도록 돕는 공급자 독립형 이메일 보안 서비스이다.
