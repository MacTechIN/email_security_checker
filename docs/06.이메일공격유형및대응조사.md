## 1. 전체 요약

이메일로 들어오는 공격은 **① 사람을 속이는 것(피싱·BEC·사칭·협박)**, **② 파일로 침투하는 것(악성 첨부·랜섬웨어 전달)**, **③ 링크로 유도하는 것(악성 URL·QR·OAuth 동의)**, **④ 계정과 사서함 자체를 노리는 것(계정 탈취·MFA 피로·이메일 폭탄)**, **⑤ 안에서 밖으로 나가는 것(개인정보·기밀 유출)** 다섯 갈래로 정리된다. 다섯 영역 모두에 성숙한 오픈소스 대응 코드가 존재하며, 대부분 Python 라이브러리로 MailShield 트레이 앱에 바로 얹을 수 있다.

핵심 결론 다섯 가지:

1. **규칙 원문이 이미 공개되어 있다.** Sublime Security `sublime-rules`(MIT, 1,000+ YAML)가 피싱·BEC·콜백 피싱·협박·HTML 난독화·서비스 남용까지 가장 넓게 다루며, MQL 로직을 Python 규칙으로 이식하는 것이 가장 빠른 확장 경로다. Neo23x0 `signature-base`(DRL), Trellix·ReversingLabs YARA, SigmaHQ(클라우드 로그)가 그 뒤를 잇는다.
2. **첨부 정적 분석은 사실상 표준 스택이 있다.** oletools + Didier Stevens Suite(oledump·pdfid·pdf-parser) + LnkParse3 + pyOneNote + pycdlib + py7zr/rarfile + YARA. 한국 특화로는 HWP의 EPS/OLE/JScript를 `olefile`만으로 검사할 수 있다.
3. **발신자 인증·유사 도메인은 오프라인으로 끝난다.** dkimpy/authheaders/checkdmarc(인증), tldextract/idna/confusable_homoglyphs/dnstwist/ail-typo-squatting(유사 도메인)은 네트워크 없이 판정 가능하다.
4. **평판 조회는 프라이버시 등급을 나눠 써야 한다.** 완전 오프라인 피드(OpenPhish community, Phishing.Database, Tranco, WhoisDS NRD, MalwareBazaar CSV, CIRCL hashlookup Bloom filter) → 해시·프리픽스만 보내는 조회(Google Safe Browsing Update/v5, VirusTotal 해시 조회, Spamhaus DQS) → URL 원문을 보내는 조회(URLhaus, PhishTank, urlscan.io) 순서로 계층화하고, 마지막 단계는 사용자 동의(opt-in)로 둔다.
5. **한국어 공개 학습 데이터는 없다.** Hugging Face·AI Hub에서 한국어 스팸/피싱 이메일 데이터셋은 확인되지 않았다(미확인). 영어 분류기(cybersectony DistilBERT F1 99.6, urlbert-tiny 3.7M 파라미터 등)는 ONNX로 내려 보조 점수로만 쓰고, 한국어는 규칙 + 자체 라벨링으로 간다. KISA C-TAS 회원 대상 "AI데이터셋 제공"이 유일한 국내 공식 경로다.

## 3. 구현 우선순위 제안

현재 MailShield 트레이 앱은 표의 7~14(첨부·랜섬웨어)와 27(개인정보 정규식)을 갖고 있다. 나머지를 비용 대비 효과 순으로 배치하면 다음과 같다.

## 4. 라이선스·운영 주의사항

- **복제 배포 시 주의 라이선스**: pyhwp(AGPL-3.0), PhishingKit-Yara-Rules(AGPL-3.0), ThePhish(AGPL), phishing_catcher·openSquat·sunzip·peepdf(GPL-3.0), Yara-Rules/rules(GPL-2.0), clamav-client(GPL-2.0), python-ssdeep(LGPL+GPL), elastic/detection-rules(Elastic License v2, 재배포 제한), Neo23x0 signature-base(DRL 1.1, 상용 제품 내 재배포 조건 확인 필요). 이들은 규칙 로직 참고 또는 별도 프로세스(사이드카) 실행으로 격리한다.
- **상업적 사용 제한 API**: VirusTotal 공개 API(상업 제품 사용 금지), Google Safe Browsing(상업적 용도 비허용 약관), Spamhaus 공개 미러·SURBL 공개 미러(비상업·저볼륨). 상용 배포 시 유료 계약 또는 대체(오프라인 피드) 필요.
- **개인정보**: URL 원문·파일 원본을 외부에 보내는 조회는 사용자 동의 후에만. 기본값은 오프라인 피드와 해시·프리픽스 조회. 원격 이미지는 절대 fetch하지 않는다(트래킹 픽셀 트리거).
- **정체된 프로젝트**: pyspf(2020), pyzbar(2023, zbar 원본 2012 중단), Yara-Rules/rules(2022), Cuckoo(2021 아카이브), ypid ransomware-file-extensions(2016). 대안: authheaders, zxing-cpp, signature-base, CAPEv2, dannyroemhild 목록.
- **한국 법제 근거**: 정보통신망법 제50조(광고 메일 표기), 개인정보보호법 제34조(유출 72시간 통지)·제24조의2(주민번호), 안전성 확보조치 기준 고시(전송 암호화). 오발송도 유출에 해당하므로 발신 DLP는 법적 의무 대응 기능이다.

##### 3. 표시명 스푸핑 · From/Return‑Path 불일치 · Reply‑To 하이재킹

- **공격 방식**: `From: "CEO Name" <attacker@gmail.com>`처럼 표시명만 위조, 또는 From은 정상처럼 보이되 Return‑Path(envelope)와 Reply‑To를 공격자 주소로 설정하여 답장을 가로챔. 표시명 안에 이메일 주소를 넣는 변형(`"ceo@company.com" <x@evil.com>`).
- **탐지 신호**:
  - From 표시명에 `@`가 포함되고 실제 주소와 다름.

  - Gmail이 붙인 `Authentication-Results: ... dmarc=fail` 또는 `dkim=none spf=softfail`.

  1. IMAP으로 받은 원문 bytes에 `dkim.verify(raw)` 실행(수신 후에도 본문 무변경이면 유효). `d=` 태그와 From 등록 도메인 비교 → DKIM 정렬.
  2. SPF는 수신 시점 IP가 필요하므로 재평가 대신 (a) 수신 MTA의 `Authentication-Results`/`Received-SPF` 파싱, (b) 필요 시 첫 신뢰 홉 이전 `Received` IP를 추출해 `spf.check2()`로 참고 판정.
  3. 발신 도메인 DMARC 정책은 `checkdmarc.check_dmarc`류로 조회 후 24h 캐시; `p=none`/부재 도메인에서 온 메일은 스푸핑 가능성 가중.
  4. 자기 조직·거래처 도메인 목록에 대해 `ail-typo-squatting`/`dnstwist` 후보를 앱 시작 시 오프라인 생성해 set으로 보관 → From/Reply‑To/링크 도메인 매칭. `idna.decode` 후 `confusable_homoglyphs`로 혼합 스크립트 검사.
  5. .NET 서비스라면 MimeKit `DkimVerifier` + DnsClient.NET 기반 `IDkimPublicKeyLocator`, SPF는 ARSoft.Tools.Net `SpfValidator`.

##### 5. 스레드/답장 체인 하이재킹 (Emotet/QakBot 스타일)

- **공격 방식**: 감염 호스트에서 훔친 실제 메일 스레드를 인용하고 "RE:"로 답장하는 형태로 악성 첨부(ZIP→VBS/LNK, 매크로 Word)나 링크 삽입. From은 원 발신자를 스푸핑하거나 유사 도메인, 실제 발송은 봇넷/탈취 계정. Unit42 사례: 탈취 후 수 시간 내 발송, 최근 메일 우선 사용.
- **탐지 신호**:
  - 제목 `RE:/FW:`인데 `In-Reply-To`/`References` 헤더 부재(정상 MUA 답장은 항상 포함) — sublime 가짜 스레드 룰의 핵심 조건.
  - 본문에 인용된 원 메시지의 `Message-ID`가 로컬 메일함에 존재하지 않음, 또는 인용 시각과 헤더 Date의 불일치.
  - 인용 스레드의 참여자 도메인과 실제 From 도메인 불일치(룩얼라이크), 답장 문구가 지나치게 짧음("Please see attached"), 첨부가 압축/암호 ZIP·LNK·OneNote·매크로 문서.
  - SPF/DKIM 정렬 실패 + 기존 대화 상대 표시명 일치.

##### 6. 콜백 피싱(TOAD) · 이미지 전용 피싱 · 제로폰트/숨은 텍스트·HTML 난독화

- **공격 방식**:
  - **TOAD**: "Geek Squad/Norton/McAfee/PayPal 구독 $399 결제됨, 취소는 +1‑8xx로 전화" — 링크·첨부 없이 전화번호만. 종종 PDF/이미지/SumUp·QuickBooks 등 정상 인보이스 서비스 악용.
  - **이미지 전용**: 본문 텍스트 없이 스크린샷 1장(피싱 문구+QR/전화번호).
  - **제로폰트/숨은 텍스트**: `font-size:0/0px/0em/0vw`, `display:none`, `color` 배경색 동일, 소프트 하이픈(U+00AD)·워드 조이너(U+2060)·ZWSP 삽입으로 키워드 분절, BIDI RTL override(`unicode-bidi:bidi-override; direction:rtl`, `<bdo dir="rtl">`), CSS 테이블 로고, base64/entity 인코딩 HTML.
- **탐지 신호**:
  - 본문·OCR 텍스트에서 전화번호 정규식/`phonenumbers.PhoneNumberMatcher` 매치 + 브랜드 키워드 + 결제/구독/환불 어휘 + 링크 0개(sublime `callback_phishing_*` 룰 로직).
  - 텍스트 파트 길이 ≪ 이미지 첨부 크기, `text/plain` 없음, 이미지가 인라인 `cid:`로 단독 렌더.
  - HTML DOM에서 `font-size` 0 계열, `display:none`, 배경색과 동일한 `color`, 렌더링 텍스트 vs 원문 텍스트의 차이율, 제어문자(U+00AD/U+200B/U+2060/U+202E) 밀도, `<bdo dir="rtl">` ≥3.
  - 표시 텍스트(hidden 제거 후)와 모델 입력을 분리해 두 번 분류 → 결과 불일치 자체가 신호.

### 5.2 악성 첨부파일·랜섬웨어 전달

#### 요약 (5줄)

1. 이메일 첨부 기반 초기 침투는 "매크로 문서 → 컨테이너(ISO/ZIP/OneNote) → 스크립트(LNK/JS/HTA) → HTML smuggling/SVG"로 진화했고, 한국은 여기에 **HWP EPS(CVE-2017-8291)/OLE/JScript** 벡터가 추가된다.
2. 정적 분석의 사실상 표준은 **oletools(v0.60.3, 2025-05)**, **Didier Stevens Suite(oledump 0.0.85, 2026-03)**, **pdfid/pdf-parser**, **YARA + signature-base(2026-08 활동)**이며 모두 Python 라이브러리로 import 가능하다.
3. 컨테이너 계층(ZIP/7z/RAR/ISO/OneNote/LNK)은 `zipfile`+`py7zr`+`rarfile`+`pycdlib`+`pyOneNote`+`LnkParse3`로 재귀 언패킹하되, 압축률·깊이·총량 제한(zip bomb)을 코드로 강제해야 한다.
4. 해시 평판은 **MalwareBazaar(무료, Auth-Key)**, **VirusTotal Public(4회/분·500회/일, 상업 이용 금지)**, **CIRCL hashlookup(인증 없음, known-good)**을 계층적으로 조합하고 MISP warninglists로 오탐을 제거한다.
5. 기존 `tray/mailshield_tray/threats.py`(magic sniff, vbaProject.bin, zip 재귀, PDF 정규식)에 위 라이브러리를 "선택적 의존성"으로 얹고, 최종 단계에 ClamAV(clamd INSTREAM)+EICAR 파이프라인 테스트를 두는 구조를 권장한다.

##### 6. HTML smuggling 첨부 (.html/.htm/.shtml/.svg)

- **공격 방식:** 첨부 HTML이 `atob()`/hex/XOR로 인코딩된 ZIP/ISO를 `Blob` → `URL.createObjectURL` → `<a download>` 자동 클릭 또는 `msSaveOrOpenBlob`으로 저장; 가짜 Office 365 로그인 폼(AiTM); SVG는 `<script>`·`onload=`·`<foreignObject>`로 동일 기법; WebAssembly로 디코더 은닉.
- **탐지 신호:** `atob(`, `Uint8Array`, `new Blob(`, `createObjectURL`, `msSaveOrOpenBlob`, `download=`, `.click()`, `String.fromCharCode` 반복, 수십 KB 이상의 base64 리터럴(디코드하면 `PK`/`CD001`/`MZ`), `<svg ... onload=`, `<script>` in SVG, `WebAssembly.instantiate`, 로그인 폼 `type="password"`+외부 `action`.
- **대응 코드/도구:** delivr-to/detections(`svg_onload_onerror.yar`, `html_wasm.yar`), signature-base `SUSP_Email_*`, box-js(2차 에뮬레이션), Strelka ScanHtml/ScanJavascript.
- **MailShield 적용 방안:** 확장자/매직(`<!DOCTYPE`, `<html`, `<svg`)으로 분기 후 위 토큰 가중 점수(Blob+atob+download/click 3종 이상 → RISK_HIGH). base64 리터럴(≥ 2KB)을 디코드해 `sniff_type` 재적용(ZIP/ISO/MZ면 RISK_HIGH, `_inspect_zip` 재귀). SVG 첨부는 `<script|on\w+=`만 있어도 RISK_HIGH.

##### 7. 랜섬웨어 전달 체인 (이메일 → 로더 → 랜섬웨어)

### 5.3 악성 URL·QR·평판 API

#### 요약 (5줄)

1. 이메일 링크 기반 공격은 "URL 자체의 평판"만으로는 잡히지 않는 형태(오픈 리다이렉트, 클라우드 호스팅 남용, QR, .ics, 첨부 내 링크)가 주류이며, **URL 추출 → 정규화 → 도메인 분해 → 오프라인 리스트/휴리스틱 → 온라인 평판 API → (선택) ML 분류**의 계층형 파이프라인이 필요하다.
2. 무료 평판 소스 중 오프라인 가능·상용 친화적인 것은 **URLhaus(abuse.ch, Auth-Key 필요)**, **OpenPhish community feed(12시간 주기 txt)**, **Phishing.Database(MIT)**, **Tranco/Umbrella Top‑1M(허용리스트)**, **WhoisDS NRD(일일 zip)**이고, 실시간 조회는 **Google Safe Browsing v4/v5(해시 프리픽스, URL 비전송)**, **Spamhaus DBL / SURBL(DNS, 비상업 한정)**, **VirusTotal(공개 API 4 req/min·500/day)**, **urlscan.io**다.
3. 룩어라이크/IDN/서브도메인 남용은 `tldextract`(BSD‑3, 5.3.2 2026‑08) + `dnstwist`(Apache‑2.0) / `ail-typo-squatting`(BSD‑2) + `idna`/`confusable_homoglyphs`로 완전 오프라인 탐지가 가능하다.
4. QR(quishing)·PDF·HTML 첨부는 `zxing-cpp`(Apache‑2.0, v3.1.1 2026‑07, Python/.NET 바인딩) + `pypdf`(6.18.0 2026‑09) / `PdfPig`(.NET) + `lxml`/`BeautifulSoup` 또는 `AngleSharp`(.NET) 조합으로 링크를 끌어내 동일 파이프라인에 투입하면 된다.
5. ML 보조는 Hugging Face의 `CrabInHoney/urlbert-tiny-v4-phishing-classifier`(3.69M 파라미터, Apache‑2.0, F1 0.99)처럼 초경량 모델을 ONNX로 내려 오프라인 실행 가능하며, `ealvaradob/phishing-dataset`(80만 URL) / PhiUSIIL(UCI, CC BY 4.0) / Kaggle `malicious_phish.csv`(651,191건)로 재학습·평가할 수 있다.

> 참고: 저장소 구조 기준으로 MailShield는 **.NET 8 Agent**(`agent/MailShield.Agent`: MailKit IMAP IDLE → `MailEventPipeline` → `DlpScanner`/`PolicyStore`), **Python FastAPI backend**(`backend/`), **Python tray**(`tray/`: Pillow 포함)로 구성되어 있어 아래 "적용 방안"은 이 세 지점을 기준으로 작성했다.

#### 공격 유형별 정리

##### 1. 본문 내 피싱/멀웨어 URL, 표시텍스트-href 불일치, 단축 URL, 오픈 리다이렉트, 다단계 리다이렉트

- **공격 방식**: `<a href="https://evil.tld">https://bank.com</a>` 형태의 불일치, bit.ly/t.co 등 단축기, `https://trusted.com/redirect?url=https://evil` 형태의 오픈 리다이렉트(신뢰 도메인으로 평판 검사 우회), 단축→리다이렉터→CDN→최종 피싱의 3~5홉 체인. rspamd 문서도 동일 사례를 대표 패턴으로 명시한다.
- **탐지 신호**:
  - href의 eTLD+1 ≠ 앵커 텍스트에 포함된 URL의 eTLD+1 (rspamd `PHISHED_URL` 로직: 동일 도메인/서브도메인은 통과, 알려진 리다이렉터/ESP 예외 필요)

##### 3. 룩어라이크 도메인, punycode/IDN 호모글리프, 서브도메인 남용, NRD, 무료 호스팅/클라우드 남용

##### 4. 트래킹 픽셀/원격 콘텍스트, HTML 폼, `data:`/`javascript:` URI

- **공격 방식**: 1×1 원격 이미지(개봉 시각·IP·UA 수집 → 표적화), CSS `background:url()`/`@import`/`<link>` 원격 로딩, 메일 본문 내 `<form method=post action=https://evil>`로 직접 자격증명 수집, `data:text/html;base64,...`로 브라우저에서 피싱 페이지 로컬 렌더링(호스트 없음 → 평판 조회 불가), `javascript:` 스킴.
- **탐지 신호**: `img` width/height ≤ 2 또는 `display:none/opacity:0`, 이미지 URL에 긴 고유 토큰 쿼리, 원격 `src` 호스트가 발신 도메인과 다름·다수, `<form>` 존재(정상 메일에서 거의 없음), `input[type=password]`, `href`/`src`/`action` 스킴이 `data:`/`javascript:`/`vbscript:`/`file:`, `meta http-equiv=refresh`, `<iframe>`, `<object>`, `<svg>` 내 `<a>`/`<script>`.
- **대응 코드/도구**: lxml / BeautifulSoup4(Python), AngleSharp(.NET, MIT), rspamd HTML 파서 심볼(참고), pytracking(트래킹 픽셀 인코딩 이해용, 미확인).
- **MailShield 적용 방안**:
  - `HtmlRiskScanner` 추가: `img[src]`, `[style*=url(]`, `link[href]`, `form[action]`, `input[type=password]`, `[href^="data:"]`, `[href^="javascript:"]`, `meta[http-equiv=refresh]` 카운트 → 점수. 전부 오프라인.
  - `data:` URI는 base64 디코딩 후 내부 HTML을 같은 스캐너에 재귀 투입(내부의 `<form action>`이 진짜 수집 서버).
  - 원격 이미지 호스트는 **절대 fetch하지 않음**(픽셀 트리거 방지) — 도메인만 평판 조회.

##### 5. 첨부 파일 내 링크(PDF/HTML/.htm/.shtml), 캘린더(.ics) 초대 피싱

- **공격 방식**: 본문은 깨끗하고 PDF "문서 열기" 버튼(`/Annots` `/A /URI`), HTML 첨부(로컬 렌더 피싱 페이지, 난독화 JS + `atob`), `.ics` 첨부 또는 Google Calendar 초대의 `DESCRIPTION`/`URL`/`LOCATION`/`ATTACH` 필드에 피싱 링크 — 캘린더가 자동 등록하여 메일을 열지 않아도 알림으로 노출. 2025년 Check Point 조사(300개 조직, 4주 4,000건)와 Sublime 보고(전통 SEG 우회율 59%)가 있으며, Zimbra `.ics` XSS(CVE‑2025‑27915)도 보고됨.

### 5.4 스팸·협박·계정 탈취·OAuth 동의 피싱·발신 유출(DLP)

#### 요약 (5줄)

1. **스팸·스캠·성착취 협박(sextortion)** 계열은 콘텐츠 분류 문제로, rspamd(4.1.5, 2026‑08‑15)·SpamAssassin(4.0.2, 2025‑08‑30)의 Bayes(OSB 토크나이저+Redis) 위에 Hugging Face RoBERTa/BERT‑tiny 스팸 분류기와 비트코인 주소 검증(`validators.btc_address`)을 결합하는 것이 가장 실용적이다. Sublime `sublime-rules`(MIT, 295개 YAML 룰)에 extortion/romance/advance‑fee/BEC 룰이 공개돼 있어 MQL→Python 규칙 이식이 가능하다.
2. **계정 탈취(ATO)**는 IMAP만으로는 인박스 룰을 볼 수 없으므로 (a) Sent 폴더 IDLE 감시로 발송량·시간대·신규 외부 수신자·제목 유사도(TLSH) 기준선 이탈을 잡고, (b) Gmail API `settings.forwardingAddresses/filters`, Graph `inboxRules`를 주기 조회하며, (c) Red Canary/Microsoft가 공개한 `New-InboxRule`/`ForwardTo`/`RSS Feeds` 폴더 등 룰 남용 시그니처를 재사용한다.
3. **OAuth 동의 피싱·디바이스 코드 피싱·MFA 피로 공격**은 메일 본문(앱 승인 링크, "verify your account", 반복 로그인 알림)과 ID 로그(Entra `Consent to application`, `AuthenticationProtocol=deviceCode`, `MFA Denied` 연속 후 성공)를 함께 봐야 하며, SigmaHQ(azure 13+20개), Elastic detection‑rules(7개 TOML) 룰이 참조 구현이다.
4. **발신 유출(DLP)**은 Presidio(2.2.364)가 2025‑07 이후 KR_RRN·KR_FRN·KR_DRIVER_LICENSE·KR_PASSPORT·KR_BRN 인식기를 갖고 있고(기본 비활성), 한국어 특화로는 ko‑pii(33종, MIT, 2026‑09 활동), KoELECTRA/KPF‑BERT NER, privacy‑filter‑korean이 있다. 문서 지문은 TLSH(py‑tlsh 5.0.0)·ssdeep, 이미지 PII는 Tesseract 5.5.3/EasyOCR/PaddleOCR로 처리한다.
5. **이메일 폭탄·대량 발송 남용·reply‑all 스톰**은 개별 메일이 정상(SPF/DKIM 통과)이라 콘텍스트 필터가 무력하며, 사서함 단위 속도(velocity)+"구독 확인" 문구 집중도+같은 시간대 비밀번호 재설정/결제 알림 존재 여부를 결합해 "사기 은폐 시도"로 격상 알림해야 한다.

#### 공격 유형별 정리

##### 1. 스팸·스캠 (선급금 사기, 로또, 로맨스, 구직 사기)

- **공격 방식:** 저비용 대량 발송 또는 소량 표적 발송. 로맨스/펜팔·유산 상속·해외 송금 대행·재택 구직 등으로 답장을 유도하고 답장 스레드에서 결제·개인정보를 요구. Sublime 룰 이름이 공격 카탈로그 역할: `bec_romance_scam.yml`, `bec_fraud_penpal_scam.yml`, `body_advance_fee_new_sender.yml`, `bec_fraud_generic_scam.yml`, `bec_student_loan_callback_scam.yml`, `spam_emoji_cash_lures.yml`, `tax_w2_impersonation.yml`, `bec_fraud_scam_lure_out_of_band_pivot.yml`(대화를 WhatsApp/문자로 유도).

##### 4. OAuth 동의 피싱(illicit consent grant), 디바이스 코드 피싱, "계정 확인" 흐름

- **공격 방식:** 공격자가 Entra/Google에 앱을 등록하고 메일 링크로 `login.microsoftonline.com/.../authorize?...scope=Mail.ReadWrite offline_access` 동의 화면으로 유도(도메인은 정상). 디바이스 코드 피싱은 `microsoft.com/devicelogin`에 코드 입력을 유도해 refresh token 획득, 이후 Authentication Broker·VS Code 클라이언트로 위장하여 PRT/디바이스 등록까지 진행(Elastic Security Labs 2025‑06‑25). 비밀번호 초기화·MFA로는 해결되지 않음.
- **탐지 신호:** 메일 측: 링크 host가 공식 IdP인데 `client_id` 미상, `scope`에 `offline_access`·`.default`·`Mail.ReadWrite`·`Files.ReadWrite.All`, 본문에 "device code/디바이스 코드 입력", "Approve this app", 앱 이름 브랜드 오타. 로그 측: Purview 감사 `Consent to application`, Entra 사인인 `AuthenticationProtocol=deviceCode`, `adrs_access` 스코프, 한 세션 ID가 짧은 시간에 여러 IP; Google Workspace OAuth 로그 이벤트(Authorize, Client ID, Scopes).

##### 5. MFA 피로(push bombing) 유인 메일

- **공격 방식:** 크리덴셜 확보 후 MFA 푸시를 반복 전송, 동시에 "IT 헬프데스크"를 사칭한 메일/Teams로 "승인 눌러 달라"고 유도. 또는 "verify your account within 24h" 문구로 AiTM 로그인 페이지 방문 후 MFA 피로 연계.
- **탐지 신호:** Entra 사인인 로그 "MFA Denied"(Sigma `azure_mfa_denies.yml`, T1621), 5~10회 거부 후 동일 IP/디바이스에서 성공. 사서함 측: IdP "로그인 시도 알림" 메일 다수 + 헬프데스크 사칭 메일 동시 도착.
- **대응 코드/도구:** SigmaHQ `azure_mfa_denies.yml`, `azure_mfa_interrupted.yml`; elastic/detection-rules issue #2440(거부→성공 시퀀스 로직); authomize/mfa-bombing(https://github.com/authomize/mfa-bombing, Okta 대상 시뮬레이터, 탐지 검증용); sublime-rules `credential_phishing_suspicious_subject_nlu_financial_urgent.yml`.
- **MailShield 적용 방안:** INBOX에서 10분 윈도우로 발신자 = IdP 알림 도메인(DMARC pass) 메일 수를 세어 ≥5이면 `MFA.PUSH_FLOOD` 경고를 트레이에 즉시 표시("승인하지 마세요" 행동 지침 포함). 헬프데스크 사칭 메일 규칙(내부 브랜드명+`support`/`helpdesk` + 외부 도메인 + "approve/승인") 매칭 시 관리자 알림.

##### 7. 뉴스레터·대량 발신 남용, snowshoe 스팸, reply‑all 스톰

- **공격 방식:** 정상 ESP(Mailchimp/HubSpot 등)의 인증된 인프라를 통해 발송해 SPF/DKIM 통과(Sublime "service abuse" 룰군). Snowshoe는 다수 IP/도메인에 소량씩 분산해 평판 필터 회피. Reply‑all 스톰은 대형 배포 목록 연쇄 답장.
- **탐지 신호:** `List-Unsubscribe`/`List-Id`/`Precedence: bulk` + 첫 발신자, Microsoft BCL 헤더; snowshoe는 콘텍스트 지문(fuzzy hash) 동일인데 발신 IP/도메인 다양 → rspamd fuzzy storage, Spamhaus CSS. Reply‑all 스톰은 Exchange Online 기준 "60분 내 5,000명 이상에게 10건 reply‑all → 4시간 차단".
- **MailShield 적용 방안:** INBOX 신규 메일 본문 정규화 후 TLSH 지문을 1시간 롤링 윈도우에 저장; 동일 클러스터가 서로 다른 발신 도메인/IP ≥ 3에서 도착하면 `SPAM.SNOWSHOE`. `List-Unsubscribe` 있고 발신 도메인이 사용자 발송 이력에 없으면 "미구독 대량메일" 라벨(경고). 같은 `In-Reply-To` 스레드에 30분 내 답장 ≥ 20 & 수신자 ≥ 50이면 `STORM.REPLY_ALL` 안내.

##### 8. 이메일 폭탄(subscription bombing) — 사기 은폐 수단

- **공격 방식:** 봇으로 수천 개 뉴스레터 폼에 피해자 주소 등록 → 시간당 1,500통 이상 정상 확인 메일 유입(Proofpoint 2025‑12‑11). 목적은 동시에 발생하는 비밀번호 재설정·송금 승인·구매 확인 메일을 묻어버리는 것. Black Basta류는 이후 Teams로 "IT 지원" 사칭 전화를 걸어 원격 도구 설치 유도.
- **탐지 신호:** 사서함 단위 수신 속도 급증, 발신자 대부분 최초 접촉, "Welcome to / Confirm your subscription / 가입을 확인" 집중, `List-Unsubscribe` 비율 급증, 폭탄 구간 안에 은행·결제·IdP 알림이 섞여 있음(격상 조건). Sublime은 "sustained spikes" 자동 감지(https://docs.sublime.security/docs/email-bomb-protection).
- **대응 코드/도구:** 전용 오픈소스 탐지기는 확인되지 않음(미확인). 구성 요소로 imapclient/mailsuite(속도 계측), `mrm8488/bert-tiny`(구독확인 vs 기타 재학습), py‑tlsh(템플릿 클러스터링).
- **MailShield 적용 방안:** `FolderWatcher`가 매 IDLE 주기 `new_uids()` 개수를 시계열로 저장 → 10분 이동평균 대비 10배 이상이며 신규 발신자 비율 > 80%면 `BOMB.SUBSCRIPTION` 경고. 동일 구간 메일을 재검사해 IdP/은행/결제/배송 확인 메일만 "폭탄 속 중요 메일" 목록으로 핀 고정하고, "IT 지원을 사칭한 전화·Teams 메시지에 응하지 말 것" 안내. 관리자 콘솔에는 ATO 의심 사건으로 승격.

### 5.5 KISA·국내 자료·법제·사칭 패턴

#### 요약 (5줄)

1. KISA/KrCERT(boho.or.kr)는 이메일 위협에 대해 별도의 "전자우편 보안 가이드" 단일 문서보다 **보안공지(사칭 피싱·큐싱·SKT 이슈·합동권고문)**, **랜섬웨어 대응 가이드라인(2023.8 개정)·STOP랜섬웨어 페이지·복구도구(Hive V3/V4 등 10종)**, **118 상담(24시간)**, **C-TAS 2.0(개방형=회원가입만, 공유형=API·승인)**으로 대응 체계를 제공한다.
2. 스팸 대응은 불법스팸대응센터(spam.kisa.or.kr)가 담당하며 **KISA-RBL은 DNS zone `spamlist.or.kr`(IPv4, 127.0.0.2=리스팅)로 무료 조회**, **화이트도메인은 SPF 등록 + 사업자등록증 첨부 후 1~2일 심사**로 등록되고 RBL 이력이 생기면 즉시 삭제된다.
3. 최근 2년 국내 트렌드는 (a) 국세청·행안부·건보·경찰청·청와대·방미통위 등 **정부기관 사칭으로 네이버/구글 계정 탈취**(HTML 첨부·"새로운 통지서/전자문서 도착" 문구·러시아/저가 신규 TLD 발신), (b) 김수키의 **LNK·JSE·HWPX 위장(이중 확장자 `.hwp.lnk`, `.hwpx.jse`), 압축·다단계 PowerShell**, (c) **예스24·SGI서울보증 랜섬웨어(2025, VPN 경계장비 침투)**, (d) 무역 BEC(4년여 1,330억 원 피해)로 요약된다.
4. 법·제도는 정보통신망법 제50조(사전동의·야간전송·표기·회피기술 금지), 개인정보보호법 제34조(72시간 내 통지·신고, 1천명 이상), 제24조의2(주민번호 처리제한·암호화), 안전성 확보조치 기준(고시 제2023-6호, 2025.10.31 개정 시행: 전송 암호화·접근통제·VPN 등)이 핵심이다.
5. 코드 자산은 **ko-pii(MIT, 주민번호·사업자번호 체크섬 포함 33개 PII)**, **pyhwp(AGPL-3.0)**, **hwp-analyzer(YARA 연동, 라이선스 미표기)**, **KicomAV(MIT)**, Trellix ATR 김수키 YARA 등이 즉시 활용 가능하나, **한국어 스팸/피싱 "이메일" 공개 데이터셋은 AI Hub에서 확인하지 못했다(미확인)** — C-TAS 회원 대상 "AI데이터셋 제공" 메뉴가 대안이다.

#### 2. KISA 스팸 대응 체계

**기관/채널**
- 불법스팸대응센터: https://spam.kisa.or.kr (본문 동적 로딩으로 fetch 실패). KISA 안내: https://www.kisa.or.kr/1060301
- 신고: 118 전화, 118 ARS(24시간), 온라인 신고. 처리 흐름: 민원접수 → 피신고인 확인 → 방통위 행정처분 요청 → 사실조사 → 과태료 부과 → 이의제기.

**KISA-RBL (실시간 스팸차단리스트)**
- 무료, 메일서버 운영자 사용 가능(등록 필요 여부 미확인). 2006년 9월부터 화이트도메인과 통합 관리.
- 기술 정보(multirbl.valli.org): DNS zone **`spamlist.or.kr`**, IPv4만, 표준 DNSBL(RFC 5782) — 역순 IP를 붙여 A 레코드 조회, **`127.0.0.2` 응답 = 리스팅**. 공식 https://www.kisarbl.or.kr (접속 거부 — 미확인).
- MailShield 활용: 수신 메일의 Received/발신 IP를 `<rev-ip>.spamlist.or.kr`로 조회하여 스팸 점수 가중.

**화이트도메인 제도** (ITEasy 가이드 https://www.iteasy.co.kr/solution/whitedomain 기준)
- 정상 대량 메일 발송자가 RBL로 차단되지 않도록 국내 주요 포털로의 전송 보장. 조건: SPF 레코드 사전 등록, 사업자등록증 첨부, 심사 1~2일. **RBL 이력 적발 시 즉시 삭제.**
- 공개 조회 API는 (미확인).

**국내 메일서버 운영자 권고**: SPF·DKIM·DMARC 적용, 화이트도메인 등록, RBL 연동, 광고성 메일은 정보통신망법 제50조 표기 준수. AI 기반 스팸 차단 협력(KISA-KT, KISA-금감원) 진행 중.
