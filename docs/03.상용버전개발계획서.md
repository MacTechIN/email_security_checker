# MailShield 상용 버전 개발계획서

## 1. 상용화 목표

MailShield를 개인 테스트 도구에서 조직이 실제 업무에 사용할 수 있는 이메일 정보유출방지(DLP)·위협감시 제품으로 전환한다. 상용 버전은 Windows Service와 트레이 UI, 중앙 관리 콘솔, 공급자 독립형 이메일 커넥터, 정책·사건·감사 시스템으로 구성한다.

상용 버전의 핵심 약속은 다음과 같다.

- Gmail, Microsoft 365, 국내 포털, 일반 IMAP 및 기업 메일을 공급자별 커넥터로 지원한다.
- 이메일 주소만으로는 공개 DNS·서버 보안만 진단하고, 메일함 접근은 인증과 동의 후 수행한다.
- 개인정보, 금융정보, 인증정보, 악성 첨부파일 및 등록 프로그램 생성 파일의 외부 전송을 감시한다.
- 관리자가 위험 사용자, 사건 근거, 처리 상태와 감사 이력을 확인한다.
- 메일 원문과 민감정보를 기본 저장하지 않으며 보안·개인정보 보호를 제품의 기본값으로 삼는다.

## 2. 상용 제품 구성

### 2.1. Windows Agent

- **MailShield Service:** 자동 시작, IMAP IDLE/API 커넥터, 로컬 DLP, 파일 출처 추적, 정책 동기화, 암호화 큐
- **MailShield Tray:** 상태 표시, 사용자 경고, Windows Toast, 일시 중지 요청, 계정 연결 및 진단 결과
- **Updater:** 서명된 패키지 검증, 단계적 배포, 실패 시 롤백
- **Local Secure Store:** Windows Credential Manager 또는 DPAPI 기반 토큰·정책·체크포인트 저장

`.pyw` 프로토타입은 개발·현장 재현용으로만 유지하고 상용 설치 패키지에는 포함하지 않는다.

### 2.2. Cloud Control Plane

- 조직·사용자·장치·권한 관리
- DNS 자동 탐지와 공급자별 인증 라우팅
- 정책 배포 및 버전 관리
- 사건·알림·승인·차단·오탐 처리
- 관리자 대시보드와 감사 이력
- 분석 작업 큐, 모델·규칙 버전, 외부 API 장애 격리

### 2.3. 지원 배포 모델

| 모델 | 설명 | 우선순위 |
|---|---|---|
| SaaS 멀티테넌트 | 조직별 논리 격리, 중앙 업데이트 | 1차 출시 |
| 전용 테넌트 | 고객별 데이터베이스·키·네트워크 분리 | 기업 고객 |
| 사내 구축형 | 고객망 내 서버, 외부 분석 제한 | 규제·대기업 확장 |

## 3. 상용 아키텍처 원칙

- Agent는 네트워크가 끊겨도 로컬 정책으로 최소 감시를 지속하고 연결 복구 후 사건을 재전송한다.
- 서버는 테넌트 ID를 모든 데이터 접근 조건에 강제하여 조직 간 조회를 차단한다.
- 위험 판정은 규칙·모델·외부 평판 결과와 근거를 함께 저장하며 모델 결과만으로 차단하지 않는다.
- 고위험 사건은 정책상 승인·보류·차단을 적용하고, 일반 사건은 사용자 확인과 관리자 알림을 조합한다.
- 메일 원문·첨부파일은 기본 비저장이다. 샘플 보관은 별도 동의, 암호화, 만료 및 접근 감사가 필요하다.

## 4. 상용 기능 범위

### 4.1. 필수 기능(P0)

- 공급자 독립형 이메일 주소·DNS·Autoconfig/Autodiscover 탐지
- OAuth 2.0 및 IMAP 앱 비밀번호 인증 라우팅
- INBOX·Sent IMAP IDLE 감시와 UIDVALIDITY·체크포인트 복구
- 개인정보·금융정보·인증정보 DLP 탐지 및 마스킹
- 스팸·피싱·악성 URL·첨부파일 해시 평판 분석
- 등록 프로그램 생성 파일의 생성·이름 변경·첨부·발송 연결
- Windows 발송 전 경고(지원 Outlook 환경)와 발송 후 조기 탐지
- 관리자 대시보드, 위험 사용자, 사건 조치, 알림, 감사 이력
- 조직 정책, 예외·허용 목록, 보존 기간 및 알림 채널 설정

### 4.2. 상용 확장 기능(P1)

- Microsoft 365 및 Google Workspace 관리형 연동
- 조직 메일 게이트웨이 연동과 중앙 발송 차단
- 행동 기준선과 계정 탈취 탐지
- 파일 샌드박스 및 첨부파일 동적 분석
- 사내 구축형 배포와 고객 키 관리
- 다국어, 다지역 데이터 저장 및 감사 보고서

## 5. 보안·개인정보 요구사항

- 계정 비밀번호를 수집하지 않고 OAuth·앱 비밀번호를 우선한다.
- 토큰은 Agent에서 DPAPI, 서버에서 KMS 또는 HSM 관리 키로 암호화한다.
- TLS 1.2 이상, 인증서 검증, 장치별 상호 인증과 키 회전을 사용한다.
- 주민등록번호·카드번호·계좌번호·건강·인사정보는 원문 대신 유형·건수·부분 마스킹 값만 저장한다.
- 관리자 권한은 RBAC와 MFA로 보호하고 민감 사건 조회·내보내기를 별도 권한으로 분리한다.
- 모든 로그인, 정책 변경, 사건 조회, 승인·차단과 데이터 내보내기를 감사한다.
- 데이터 보존 기간과 삭제 작업을 테넌트별로 설정하고 삭제 증적을 남긴다.
- AI·외부 평판 API로 전송하는 데이터는 최소화·비식별화하고 공급자별 전송 동의를 관리한다.

## 6. Windows 상용 배포

- 서명된 MSIX 또는 MSI로 설치한다.
- Windows Service는 제한된 서비스 계정으로 실행하고 트레이 UI와 Named Pipe로 통신한다.
- Intune·그룹 정책·명령줄 무인 설치를 지원한다.
- Stable, Pilot, Emergency 채널을 분리하고 단계적 롤아웃한다.
- 업데이트 패키지 서명 검증 실패 시 설치하지 않으며 이전 버전으로 롤백한다.
- 서비스 중지·제거·정책 변경은 관리자 권한과 감사 기록을 요구한다.

## 7. 품질 및 운영 기준

### 7.1. 출시 차단 기준

- 테넌트 간 데이터 노출, 토큰·개인정보 로그 노출, 서명되지 않은 업데이트가 0건
- P0 기능의 단위·통합·E2E·보안 테스트 통과
- Windows 재부팅, 절전 복귀, 네트워크 단절, 토큰 만료와 서버 장애 복구 검증
- 정의된 개인정보·금융정보·악성파일 데이터셋의 정밀도·재현율 측정 완료
- 지원 공급자별 연결·IDLE·재연결 테스트 완료
- 설치·업데이트·롤백·제거 및 데이터 삭제 절차 문서화

### 7.2. 운영 모니터링

- 온라인 Agent 수, 버전·정책 분포, 마지막 동기화 시각
- IDLE 연결 수, 재연결률, 분석 큐 지연, 외부 API 오류율
- 위험 사건 수, 평균 관리자 확인 시간, 알림 성공률
- 개인정보 탐지 오탐·미탐 피드백과 규칙·모델 버전별 품질
- CPU·메모리·디스크 사용량과 Agent 크래시율

## 8. 단계별 출시 계획

### Phase 1: 상용 기반(4주)

- .NET Windows Service·트레이 셸과 서명된 설치 패키지
- FastAPI 테넌트·장치·정책·사건 API
- PostgreSQL RLS 또는 동등한 테넌트 격리
- IDLE 체크포인트 영속화와 오프라인 큐
- 기본 DLP·첨부파일·알림·감사 기능

### Phase 2: 파일럿(4주)

- 3~5개 조직, 지원 Windows·메일 환경 제한 운영
- 정상 업무 오탐률과 Agent 자원 사용량 측정
- 개인정보 보호 영향평가, 침투 테스트와 장애 복구 훈련
- 운영자·관리자 매뉴얼 및 고객 지원 절차 확정

### Phase 3: 정식 출시(4주)

- 공급자별 커넥터 안정화와 설치 자동화
- SLA·요금제·지원 채널·장애 공지 체계 확정
- 외부 보안 점검 결과 반영
- Stable 채널 정식 배포 및 단계적 업데이트

## 9. 상용화 완료 정의

상용 버전은 P0 기능과 출시 차단 기준을 모두 충족하고, 파일럿 조직에서 실제 메일 흐름을 검증하며, 보안·개인정보·운영 문서가 승인되었을 때 출시 후보로 판정한다.
